1. 収集（店本人の発信だけ・ここで得たものが根拠になる）
S1

店の公式サイト巡回

告知一覧・お知らせを巡回する。大手チェーン（M1g）の主入口はここと EC 一覧新

S2b

公式サイトの過去分巡回

削除されない限り残るので遡れる。マスタ登録の直後は過去分を対象に含める

X で溢れたぶんは Wayback から拾い直す（§1-2c）。3〜5日遅れるので締切には間に合わない新
S2

店の公式X取り込み

取得時AIで解析。新着のみ・遡れない
添付画像も投稿本文の一部として保存する新

公式本文に締切が無い 291 回のうち 226 回は締切が画像にあった（2026-09-05）
S3

公式EC・応募ページ収集

EC 一覧を巡回し、投稿内の外部リンクを展開して実ページを取る

S4

外部フィード新

新着を受け取る口。値の根拠にはしない（§1-5）

S6

共有基盤の新着新

主催者ページを毎日読む。法人名が一致した店だけ登録・課金0

3. マスタ（処理の起点）
M1

店マスタ

正規名・表記ゆれ・公式X・公式サイト・共有基盤URL・所在地

公式Xが無い店は S2 に到達できない。育成は D1 が担う
M1g

ゴールデンチェーン（大手指定）新

束ねてよいのは表示の枠だけ。権限は束ねない

  • 枠＝canonical_name ＋ store_keys[]（52チェーン）
  • 権限（公式X・店サイト・共有基盤）は完全一致のみ
  • カードに入るのは本部の告知。支店だけの回は行へ
M2

商品マスタ新

正本は各ゲームの公式一覧。階層は 弾 → 商品

  • 販売単位（BOX・パック・再販）は商品でなく行の属性
  • 形態が読めない行は set_only で保留し、推測しない
  • AI は M2 の中から選ぶだけ。名前を作らせない
M3

共有基盤の持ち主新

Googleフォーム・e-starbox・LivePocket の URL がどの店のものかを登録する

M5

語彙新

状態を表す語の正本。値の一覧と「その語で止めるか」を1か所に置く（§11-2）

2. 発見の補助経路（値は使わない）
M4

まとめ一覧新

まとめのホストはこの一覧1本。判定を各所へ書き写さない

D1

まとめからの発見

記事から取り出すのは3つだけ

  • 未登録の店・支店
  • 店の公式Xアカウント
  • 応募先URL（共有基盤を含む）
締切・商品・条件などの値は取らない。記事URLは根拠にも応募先にもしない
例外は Amazon の1社だけ。使ってよいのは受付中かどうかの状態だけで、URL は配らない（§0-1 原則1）新
4 / 11-1. 正規化と鍵
N

店名・商品名の正規化

マスタの正規名へ寄せる。未知語はマスタ育成（§3-3）へ回す

N2

引きの鍵の一致（索引）新

画面・台帳・権限が同じ鍵で引く。落とす記号が場所ごとに違うと、同じ店が別物になる

L

候補台帳

まとめの記述は値の根拠にしない。取得元と応募先は別の根拠として持つ

鍵は締切から作る。締切が無い回は暫定回で、締切が分かったら正式な回を起こす（書き足せない・§5-1）新
L2

同一性の鍵と発番新

同じ回を同じ回と決め、ID を振る。行を手で消さない（台帳が壊れる）

6. 確認の主経路（材料は S1〜S4 で取った本文だけ）
T

通過率の計測新

部品の出口で
in / out / dropped / held
と理由（語彙は M5）を書く。台帳は読み直さない

鳴らすのは: 0に張り付き／走ったのに行が無い（配線切れ）／前日比 ±30pt／保留が増え続ける／表はあるのに引けない（N2）／押せなかった run／行の主張と main の実物の食い違い
見張りは health-watch。巡回とは別の基盤に置く
M1g の店がどこで止まっているかは extra.m1g に。しきい値はまだ入れない
V1

公式根拠の取得

優先は 公式サイト → 応募ページ → 公式X。過去分は公式サイトから回収する

V2

URL展開・正規化

短縮を展開して最終URLを得る

V4

応募ページの本文取得

システムが URL を開いて読む

V3

品質検査

日付の整合・URL の持ち主（M3）・重複

V5

応募ページ確認AI（材料は取得した本文と画像だけ）

応募URL ／ 応募開始日 ／ 締切 ／ 当選発表日 ／ 応募方法 ／ 受け取り方法 ／ 応募条件

本文に無いものは「なし」と返させる。埋めるのは F の仕事で、AI に推測させない
V7

回と行の結び付け（刻印）新

どの回がどの配布行かを刻む。刻印は身元より優先されるので、ずれると別支店の情報が出続ける

H1

保留

確認できない回はここへ。捨てない

H2

保留の解消

公式サイトの登録で再取得。打ち切るのは公式が無い店だけ

人の決着は自動判定の入力に戻す。戻していない決着は、次の巡回で消される新
保留は人が見られる場所に出す。数だけ増えて誰も見ない状態を作らない新
V6

店頭のみ（例外）

告知のみ・店頭QR 等。URL 無しを欠けとしない

F

既定値の適用

開始日が無ければ告知日・地域が不明なら全国。「空である」と「確認できていない」を混ぜない

U

判定定義の一元化新

公式か・まとめか・応募ページか の判定は1か所。直書きを見つける試験で分散を止める

8. 配信
P

配信の関門 ─ 満たす回だけ配る

  • 公式根拠を1本以上持つ
  • 品質検査を通過している
締切では落とさない新。締切が過ぎた回も配信し、受付終了として表示する側で扱う。 当選発表タブ・通知ベル・LINE通知が締切後の行を使うため（2026-09-04 実測で、締切超過 143 行のうち 75 行は発表日が未来）
免除は Amazon の1社だけ新。公式告知が存在しない招待制のため状態だけ通す。通した行は応募先URLを空にしてから配る（§8-1）

大手チェーン（カード）

全店舗の抽選（行）

当選発表・通知新
