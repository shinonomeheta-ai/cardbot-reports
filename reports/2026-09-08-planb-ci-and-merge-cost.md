## 2. 【判断が要る】マージすると **AI へ 340回 送り直し**になる

**`EXCERPT_CONTRACT_VERSION` を上げると、抜粋の内容が変わっていない回も
指紋が変わる。** `candidate_ai_cache.round_fingerprint()` が

```python
return f"v{int(r.get('excerpt_version') or 旧版の抜粋)}:{指紋}"
```

と**版を指紋へ混ぜている**ため（「前の版で出した答えを新しい版の答えとして
使い回さない」——設計どおりの挙動）。

実測（時点 2026-09-08・母数 `rounds_of` 2,885回）:

```
#1468 後に抜粋 ok            2,204   ← 全部が指紋の変わる回
  active × AI 確認済み         340   ← **送り直しになる**
  active × AI 未実行           784   （もともと送る対象）
  その他（期限切れなど）       1,080  （送らない）
```

**課金が発生しうるので、私からはマージしない。** 判断を仰ぐ。

判断の材料:

* **340回は「答えを持っているのに聞き直す」ぶん**。抜粋が実際に変わったのは
  一部（metrics の実測では 285回のうち 68回で本文が変わった）なので、
  大半は**同じ本文で同じ答えが返る**可能性が高い
* 版を上げないと、**保存済みの抜粋（末尾だけの36字など）が残り続ける**。
  差分化の関門（`material_fingerprint` ＋ `excerpt_version`）が
  「入力が同じ回は作り直さない」なので、版を据え置くと直しが効かない
* 前回の版上げ（16・2026-09-04）でも同じことが起きている

**中間案があるなら「版を上げずに材料指紋だけで作り直す」だが、それをすると
`round_fingerprint` が同じままなので、新しい抜粋に対する古い答えが
`ai_status` として残る**（AIの答えと渡した本文が食い違う）。設計の意図に反する
ので、私からは勧めない。

## 4. `git stash` で事故を1件（全セッションへ）

**`git stash` の棚はリポジトリで1つ。worktree ごとではない。**

自分の worktree で `candidate_evidence_excerpt.py` だけ stash して 90秒の測定を回し、
`git stash pop` したら**別セッションの WIP**（`candidate_contract.py` /
`passrate.py` / `vocab_master.py` / `vocab.gen.mjs` / `roundup-daily.yml` /
`vocab_history.jsonl`）が展開され、3ファイルが未解決になった。
自分の stash は棚から消えていたので、**逆に誰かが私の stash を pop した**と見られる。

`git reset --hard HEAD` で**自分の worktree だけ**戻した（成果はコミット済み）。
**相手の stash は棚に残っている**（pop が衝突したときは消えない）。棚には3本ある。

前後を測るときは stash ではなく**別の worktree を切る**のが安全。
