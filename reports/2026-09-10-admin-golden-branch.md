# 管理画面: チェーンタブの抽選情報をゴールデンデータと支店で分けた（PR #1515）

**指示（本人・2026-09-10）**

> 管理画面の抽選情報をゴールデンデータと支店で分けて管理したい

分ける場所は選択肢を出して確認し、**「店舗管理のチェーンタブ側で分ける」**（＝抽選情報を
チェーン起点で見る）を選んでいただいた。

---

## 1. 何が問題だったか

利用者のカードに入るのは**チェーン全体の抽選（本部の告知）だけ**で、支店だけの抽選は
入れない（設計書 §3-1-1-c）。ところが**管理画面にはその区別がどこにも出ていなかった**。

「この店の抽選が出ない」と言われたとき、

- 本部の告知なのにゴールデンデータ台帳の `store_keys` に無いから出ない（＝直せる）
- 仕様どおり支店だけの抽選なので出ない（＝直すものではない）

のどちらなのかを、画面から言えなかった。

## 2. 入れたもの（PR #1515・未マージ）

https://github.com/shinonomeheta-ai/cardbot/pull/1515

店舗管理 →「チェーン」タブに、次を足した。

| 置いたもの | 中身 |
| --- | --- |
| 上の件数 | 本部の回／支店の回／対応付けなし の3つ |
| 絞り込み | すべて・本部の回あり・支店の回あり・台帳に対応付けなし |
| 表①ゴールデンデータ（本部の回） | `golden_chains.json` の全チェーン。tier・裏取り・店名の鍵・本部の回・対応するチェーン台帳。行を開くと**回が並ぶ**（応募URLは全文） |
| 表②チェーン台帳（支店の紐付け） | 既存の表に「本部の回」「支店の回」の列を追加。編集を開くと本部の回・支店の回が**別枠**で出る |

**表を2つに分けたのは、名簿が2つあるから。** ゴールデンデータ台帳（55チェーン）と
チェーン台帳（9チェーン）は別の名簿で、**実測では名前が1件も重ならない**
（`カードラボ`／`C-labo`、`ゲオ`／`GEO`）。片方だけを並べると、ゴールデンデータの
55チェーンが画面に1つも出ない。

### 決まりごと（守ったこと）

- **判定は増やさない。** 本部の回かどうかは `golden-chains.belongsToChain`
  （`store_keys` の完全一致＋`chain_campaign` を宣言した店だけ前方一致）**1本**を呼ぶ。
  画面にも新しいモジュールにも物差しを書き写していない（試験で留めた）
- **完全一致を前方一致に緩めない。** 緩めた瞬間に支店の抽選が本部の回として入る
- 支店の回は**人が紐付けた支店だけ**を数える。名前が似ているだけの店は数えない
- **取得の失敗を「0件」と言わない。** 読めなければ理由を出し、件数の列は「—」にする
- ゴールデンデータ台帳は**読むだけ**（同じ台帳を2か所から書けるようにしない）

### 変えたファイル

    web/app/lib/chain-lotteries.mjs          分ける純関数（新規）
    web/app/lib/chain-lotteries-load.mjs     材料の取得・失敗は投げる（新規）
    web/app/admin/chain-panel.js             2つの表・絞り込み・回の一覧
    web/app/lib/chain-lotteries.test.mjs     判定の試験13件（新規）
    web/app/admin/chain-lotteries-panel.test.mjs  配線の試験6件（新規）
    web/app/admin/chain-lotteries.e2e.mjs    実ブラウザの試験13件（新規）

## 3. 実データ（origin/main `d29574d7`・2026-09-10 時点）

| 数 | 値 | 定義 |
| --- | --- | --- |
| 抽選の行 | **488** | `web/public/data/lotteries.json` の `lotteries` |
| ゴールデンデータ台帳 | **55チェーン** | `golden_chains.json` の `chains`（`excluded` を含む） |
| チェーン台帳 | **9チェーン** | `stores.json` の `chains` |
| ゴールデンで拾える抽選行 | **59 / 488** | `belongsToChain` が当たった行 |
| 回が当たるゴールデンチェーン | **24 / 55** | 1件以上拾えたチェーン |
| 店名の鍵が空のゴールデンチェーン | **0 / 55** | いまは全チェーンに `store_keys` がある |
| チェーン台帳の行があるゴールデンチェーン | **0 / 55** | **名簿が重なっていない** |
| チェーン台帳9社の支店の回 | **36件** | 紐付け済みの支店の回（6社に付いている） |

根拠データ:
https://raw.githubusercontent.com/shinonomeheta-ai/cardbot-reports/main/reports/data/2026-09-10-admin-golden-branch.json

**読み方**: いまチェーン台帳（9社）に「本部の回」は0件で、ゴールデンデータ台帳の側にだけ
本部の回がある。2つの名簿が交わっていないので、**この画面はいまのところ
「ゴールデン＝本部の回だけの表」と「チェーン台帳＝支店の回だけの表」に見える**。
名簿を寄せるかどうかは業務の判断なので、こちらでは寄せていない（判断待ち①）。

## 4. 試験

| 何を | 結果 |
| --- | --- |
| `node --test app`（全体） | **3,690 / 3,690 緑**（新規19件を含む・枝由来の赤0） |
| 実ブラウザ 1280×900 / 390×844 | **13 / 13 緑**（`fetch` を差し替え・外部へは1件も出していない） |

実ブラウザでは、決め打ちの材料（本部の回1件・支店の回3件・よその店の回1件）を入れて
「本部の回に支店の回が混ざらないこと」「よその店の回がどちらにも出ないこと」
「390px で本体が横へ動かないこと」を測っている。1280px と 390px の絵も撮って目で見た。

## 6. 判断待ち

1. **2つの名簿を寄せるか**（`カードラボ`／`C-labo`、`ゲオ`／`GEO`）。寄せると
   チェーン台帳の支店の回がゴールデンデータのチェーンに繋がり、
   「この大手チェーンの支店の告知が何件あるか」が1画面で見えるようになる。
   ただし別名の追加は `candidate_round_id` を動かすので、移行中は入れない決まり
   （別名を足すと鍵が動く）。**寄せ方（ゴールデン側に別名欄を足す／チェーン台帳側の
   正式名を台帳名へ合わせる）も含めて指示をいただきたい。**
2. 支店の回を**紐付け前の支店**まで広げて数えるか。いまは人が紐付けた支店だけで、
   名前が似ているだけの店は数えていない（誤って本部扱いしないため）。
   「支店の候補」欄には出ているので、そこに件数を添えることはできる。
3. PR #1515 をマージしてよいか。
