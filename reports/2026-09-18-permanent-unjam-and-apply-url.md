## 1. 詰まりの恒久対策（#1609 / #1610 / #1611）

関門（`test_data_contract`）は all-or-nothing で、**1行の傷で writer の push が丸ごと止まる**。
収集は動いているので run の中身は普通に見え、配信だけ黙って固まる。

    09-15〜17  promote-provisional 10回連続 failure（「期間が逆」の1行）
    09-16〜17  nyuka-watch / update-data が丸一日停止（#1600 と関門の食い違い）

入れたのは4段（すべて合成アクション1か所・配線は試験で固定）。

    ① 隔離      契約に反する欄だけ空にする（行は消さない・値は捏造しない）
    ② 作り直し   隔離で変わったら影スナップショットと持ち主レポートを揃える
    ③ コミット   直しをコミットへ入れる（**関門が見た状態＝押す状態**）
    ④ 関門      最後の砦として残す（0件・game空の割合などはここで止める）

③は実測で見つけた穴。隔離だけ入れた回は**緑になって push まで届いたのに、押された
`lotteries.json` に期間が逆の10行が残っていた**（関門が嘘をつく状態）。

あわせて `promote-provisional` / `promote-now` / `resolve-urls` は `alert_incident` の
呼び出しが**1つも無く、10回落ちても誰も気づかなかった**ので、失敗・復旧の通知を足した。

## 4. 招待リクエスト制（#1616）

招待/リクエスト制には**締切という概念が無い**。応募ページも公開されていないので、
締切を待つと永久に配れない。`invite_request`（Amazon・ノジマオンライン）を第一条件として、
受付中の見方を2つ用意した（まとめの合図が直近／公式根拠が直近・鮮度7日）。

あわせて `roundup_seen` の台帳を存在しない `load()` で読んでいたのを直した——
**合図を1件も読めていなかった**（`roundup_rows.py` も同じ誤り）。

## 5. 応募先の運び忘れ 448件（#1615）

生きている応募回 1,948 のうち、応募先が出ていたのは **118件（6%）**。
`not_carried`（関門は通ったのに運ばれていない）が 157件、
「URLは関門を通るのに `page_role` が announcement」が 162件（**本店126・支店36**）。

原因は「**行のどの欄にURLがあったか**」への依存。応募先の候補として見るのは6欄で
`source_url` は入らず、巡回の経路ごとに同じURLが違う欄へ入るため、経路が変わるたびに落ちた。

**依存を切った。** 関門（`apply_reject_reason`・正本1か所）を通るURLが**根拠にあれば**
応募先にする。欄の名前に依存しないので新しい経路でも落ちない。

- 二重管理の確認: 判定の一覧を書き写していないことを試験で固定
- 水漏れの確認: まとめ・X投稿・検索・短縮・サイトのトップは今までどおり落ちる（試験で固定）
- 修復が入れたURLに混ざってはいけないものは **0件**（実測の2件は修復前からの別件）
- 昇格する4 workflow すべてで昇格の前に通し、**昇格を呼ぶ workflow の増減にも気づく試験**を追加
