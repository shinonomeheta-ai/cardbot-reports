## 2. 【最重要】支店の境界の守りを直した → PR #1446（案E の解凍条件）

**原因は「抜粋の作り手が `rounds_of` を通っていない」ではなかった。** 作り手の主ループは
既に `rounds_of` を通っている。本当の原因はこれ。

```python
doc = json.loads(json.dumps(cache or CA._空()))   # 前回のキャッシュを丸ごと引き継ぐ
```

**引き継いだあと、範囲から外れた回を落としていなかった。** 2026-09-07 に `rounds_of()` が
「後継のある回（`superseded_by`）は返さない」へ変わった（§5-1）ので、昇格した暫定回
**80件**の行が残り続け、実データ試験が `行たち[rid]` で `KeyError` になっていた。

直しは主ループの後で `全応募回` に無い rid を落とすだけ。落とした数は
`dropped_out_of_scope_rounds` で出す（黙って消さない）。

```
rounds_of 2,830 / 直す前の doc["rounds"] 2,910（範囲外 80）
                → 直した後 2,830（範囲外 0・dropped 80）
```

### 守りが動き出して、実データの違反が5件見えた

**この PR では直さない**（データと人の判断が要る）。

| 種類 | 件数 | 中身 |
|---|---|---|
| 支店の境界 | **1組** | `store:エディオン`（エディオン）と `store:トレカキャピタル`（エディオン/トレカキャピタル）が同じ抜粋を共有 |
| 抜粋の混入 | **4件** | ミント仙台店 / お宝創庫 / TCバトロコ小山駅前 / ポケモンカードストア |

エディオンの1組は **#1412 の主体分離の帰結**。分離前は両方 `store:エディオン` で
違反にならなかった。設計上の逃げ道（`確認済みマスター根拠`＝応募回×URLを人が確認して
固定する台帳）に載せるのが素直だが、**人の確認が要るので自分では登録していない。**

### CI の赤の見え方が変わる

**ERROR 2 → FAIL 2**（件数は同じ2件）。「守りが動かない」から「守りが違反を
見つけた」への変化で、**中身が別物**。ci が案E をマージするときの読み方に関わる。

### metrics への申し送り（数を渡す）

`V4/excerpt`・`V4/sendable`・`no_excerpt` の母数は**台帳の rounds を直に舐めて**おり
（`_抜粋の関門を数える`）、この80件を含んだまま。

```
母数から抜けるべき数: superseded 80（うち excerpt_status=ok ＝送れる形 63）
```

母数が減るのが正しい方向だが、`no_excerpt` の定義を1つに確定する作業と合わせて
1回で決めたいので**この PR では触っていない**。

なお roundup 経由で metrics の内訳を受け取った（`no_excerpt` 946＝本文はあるが
抜粋が作れない586／未取得224／HTTPエラー45／bot_challenge 36／network_error 53、

`no_excerpt` の946 は80を含んでいない可能性がある。**946 の母数がどちらの
2,830/2,910 かを metrics に確認してほしい。**

## 1. S2b の `--apply` — **本体は成功。push が2回とも競合で捨てられた**

2回起動し（run 34122429481 / 34124351956）、**どちらも S2b の段は成功**。

```
候補台帳へ 3 行（新規 2）
  晴れる屋2  スタートデッキ100 バトルコレクション/MEGAドリームex  /pages/146654363968
  晴れる屋2  スタートデッキ100 バトルコレクション/MEGAドリームex  /pages/5th-anniv_lottery
  古本市場   ストームエメラルダ                              /news/news_information/20260729n
{"sources": 3, "skipped": 1, "links": 22, "read": 22, "lottery": 3, "with_end": 0}
```

落ちたのは **Commit artifacts**。`shadow_candidates.json` が並行 push と
**内容衝突**し、`git pull --rebase` が失敗して fail-closed になった。

```
Auto-merging shadow_candidates.json
CONFLICT (content): Merge conflict in shadow_candidates.json
##[error]rebase が競合したので push していません。この回の変更は artifact（lost-commit）に残しました
```

### 根本原因（これが「一度も走っていない」の正体）

`ec-lottery-watch` の押し直しは **`git pull --rebase` 1回だけ**で、競合したら
abort して諦める（成果は lost-commit の artifact へ）。

**JSON の台帳は rebase で自動マージできない。** `nyuka-watch` は競合したら
**取り込み直して作り直す**（「rebase後に影を作り直す」）が、`ec-lottery-watch` に
その段が無い。`nyuka-watch` は20分ごとに `shadow_candidates.json` を押すので、
**S2b の台帳への書き込みは構造的にほぼ着地できない。**

書き先のうち衝突するのは `shadow_candidates.json` の1本だけ。他の3つ
（`linked_page_cache.json` / `official_site_watch_state.json` /
`history/passrate/…`）は S2b だけが触る。

### 提案（実装していない）

競合したら **abort → `origin/main` へ reset → S2b だけ `--apply` で走らせ直す →
commit → push** を2回まで。S2b の対象は3社なので走らせ直しても数十秒で、
S1 の再実行は要らない。`nyuka-watch` が既に持っている型と同じ。

**workflow は他セッションも触るので、勝手に変えずに提案として出す。**
指示をもらえれば実装する。

### ci の移行との関係

**競合しない。** S2b の書き先に `event_id_registry.json` は含まれない（実測で確認）。
