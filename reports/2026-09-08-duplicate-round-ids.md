# 1. 補正は名前を切っていませんでした。**同じ `round_id` の行が2つ**ありました

product から「補正が弾名を壊しているように見える」として渡された1件です。

```
round_id  rnd_7942188951610d00（2行とも同じ）

A  store '北国書林辰口店 CARD BOX' ／ product 'BRIGHTNESS OF HOPE'
   url https://x.com/Cardbox_tatsuno/status/2091820522334290055 ／ note 'meli-melo'
   last_seen 2026-09-08T15:21:03

B  store '北国書林辰口店 CARD BOX' ／ product 'BRIGHTNESS'
   url ''（空）／ note ''（空）
   last_seen 2026-09-08T15:33:47   ← **12分あとに増えた行**
```

game（ドラゴンボール）・source_url・締切は同じです。**補正の前後で名前が変わって見えたのは、
`zip(前, 後)` が別々の行を並べていたから**で、補正そのものは名前を切っていません。

**あとから増えた B のほうが、商品名の末尾「 OF HOPE」が落ち、url と note も空**です。

**5組とも締切が過去**なので、いま画面には出ません。ただし `round_id` は1行に1つのはずの
札です。**同じ根が生きているなら、締切が未来の回でも起きます。**

## 店名も崩れている可能性

`北国書林辰口店 CARD BOX` は、記憶にある「まとめ記事の見出しが前に付いて店名が連結する」型に
見えます（X の主は `@Cardbox_tatsuno`）。**同じ行で店名も商品名も崩れている**ので、根が
1つの可能性があります。**roundup へ渡しました。私は台帳に触っていません。**

# 2. 控えの赤は、3つの原因の差し引きでした

`test_本物の控えが行の数だけある`（main の既知の赤）の内訳が、ぴったり合いました。

```
刻んだ行 325 − 同じ鍵の重複 4 − 控えに無い鍵 7 + 控えにだけある鍵 6 = 320 = 控えの数
```

**1つの原因ではありません。** 最初、私は「重複5でちょうど説明できる」と読みかけましたが、
**鍵の作り方（`event_id#round_id`）を間違えていました**。数え直すと上のように割れます。
北国書林の組は**商品名が違うので `event_id` も違い**、重複ではなく「控えに無い鍵」の側に
出ます。

**`test_成果物の行と控えの鍵がつながっている` の7件は別の原因**です（控えは巡回が作る
生成物で1回ぶん遅れる、と試験の但し書きにあるとおり）。**2つの赤は同じ根ではありません。**

> **今日6回目の「見ている入れ物が1つ足りない」でした。** 差が5、重複が5、と数が合ったので
> 「説明できた」と書きかけました。**数が合うことは説明が正しいことの証明になりません。**
> 内訳まで割ってはじめて、3つの原因の差し引きだと分かりました。
