### 2. 汚染源（特定）

真の吸収7件は、**2つの処理が重なって**起きている。

#### 段1: 候補と配布行の突き合わせが、別の支店に当たる

吸収された7件の中身を見ると、**同じチェーンの別支店**のURLが入っている。

| event の店 | 入った他店のURL |
|---|---|
| 八文字屋北店（Cardbox） | `x.com/Cardbox_okazaki/…`（岡崎店） |
| TSUTAYA鈴鹿中央通店 | `x.com/wtokazaki_card/…`（ウイングタウン岡崎店） |
| TierOne 浜松店 | `x.com/TierOneshibuya/…`（渋谷店） |
| ［トレカ］広店（フタバ図書TSUTAYA） | TSUTAYAリノアス八尾店 |
| TSUTAYA AZ岡南店 | TSUTAYAリノアス八尾店 |
| magi立川駅前店 | magiトレカ / magi福岡天神店 |
| ビックカメラ柏店 | ビックカメラ店舗 |

**`TierOne浜松店 ← 渋谷店` と `TSUTAYA鈴鹿中央通店 ← 岡崎`** は、[第1区切りの報告]
（2026-09-04-gate-impl.md）で「刻印が別支店を指していた3件」として直したものと
**同じ組み合わせ**。つまり突き合わせが別支店に当たる経路は既知で、そこから
その支店のURLが行へ運ばれている。

#### 段2: 発番が index 全体を走査して、既存 event を再利用する

決定打はこれ。`promote_candidate_decisions.py` に 2026-09-01 14:40 に入った
**`684553de fix: 発番にURL寛容の同一主体照合`**。

```python
# **URLだけ違う既存素性があれば、その案件を使う**
for 既鍵, 既eid in index.items():
    if LIO._同じ主体か(鍵, 既鍵):
        eid = 既eid
        break
if eid:
    events[eid]["identity_keys"].append(鍵)   # ← 別店URL付きの鍵がここで入る
    index[鍵] = eid
```

問題は3つ。

1. **index 全体（2,800本超）を走査して、最初に当たったものを使う。** 辞書の並び順に
   依存し、複数が当たっても選び直さない
2. **当たった数を見ていない。** 2つ以上の event が「URLだけ違う」に該当しても、
   最初の1つを黙って選ぶ
3. **段1で行が別支店のURLを持っていると、そのURL付きの鍵が既存 event へ追記される。**
   `_同じ主体か` は seller の一致を見るが、**seller は行の店名**なので、
   *行のURLが他店のものである* ことは検査できない

**時期が一致する。** このコミットは 9/1 14:40。真の吸収は 8/31=0 → 9/2=3。
