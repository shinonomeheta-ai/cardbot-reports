### ② なぜ商品名を途中で切るのか——**理由が2つあり、別物です**

**口A（まとめ・`build_lotteries_melimelo.extract_set`）: 空白で分割して先頭トークンだけを採る。**

    t = re.split(r"[　\s]{1,}", t.strip())   # 全角/半角スペースで分割
    t = next((s for s in t if s), "")        # ← 先頭の1つだけ

実際に動かして再現しました。

    'ドラゴンボール BRIGHTNESS OF HOPE　ブックオフプラス新宿駅西口' → 'BRIGHTNESS'
    'ポケカ 30th CELEBRATION　MINT GAMES池袋店'                  → '30th'
    'ポケカ ストームエメラルダ　晴れる屋2／…'                        → 'ストームエメラルダ'（無傷）

**日本語の弾名は空白が無いので無傷、空白を含む英語名は必ず切れます。** 文字数の上限ではありません（`[:120]` の切り詰めは別にありますが働いていません）。

**口B（弾の名前の表）: 切っていません。「照合用の1語」を弾の名前として使っています。**

`official_x_intake.set_names()` は弾の名前の表を2つの元から作ります。**`set_images.json`（295件）と `watchlist.json` の `include`（21件）**です。この `include` は `build_watchlist.derive_include` が作ります。

    tokens = core.split()
    if len(tokens) <= 2: return [core]
    return [max(tokens, key=len)]        # ← **最も長いトークン1つ**

    'ブースターパック DUAL EVOLUTION [FB09]'     → include ['EVOLUTION']
    'ブースターパック BRIGHTNESS OF HOPE [FB11]' → include ['BRIGHTNESS']

**`include` は「その商品を見つけるための1語」であって弾の名前ではありません。** それを弾の名前の表に混ぜているので、`product_of` が**照合用の1語をそのまま商品名として返します**。

いま表に入っている危ういものは **`'EVOLUTION'` と `'[FB10]'` の2つ**です（品番だけの `[FB10]` も弾名として使われます）。

**口Bは開いています。** `product_of` を使うのは EC の一覧の巡回と公式X の取り込みで、どちらも動いています。

正しい名前で取り込み直すと、既存の候補が直るのではなく**別の候補ができます**。実際 2026-09-04 に人が正しい名前を入れたとき、`cevt_79c6430a10156edc`（`BRIGHTNESS`）は残ったまま `cevt_2fd82849591e52bd`（`BRIGHTNESS OF HOPE`）が増え、**同じ `round_id` の配布行が2本**になりました。store-name-a が見つけた重複はこれです。
