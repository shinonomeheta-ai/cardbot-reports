## 3. 記録した学び

`一覧の場所を名前で決めない` を記憶へ入れた（`list-page-not-by-name`）。

> `news` `blog` `information` という名前は、その店が何を置く場所として使っているかを
> 表さない。名前で決めると、動いているのに0件という顔になる（読めている・記事も
> 取れている・抽選だけ0）。一覧を登録する前に、その一覧から取れた記事を実際に判定へ
> 通して「抽選と判定された数」を見る。0 なら場所が違う。
>
> 同じ日に近い罠をもう1つ見つけている——`href` 末尾の空白で記事を全部捨てていた。
> **0件のときは「場所が違う」と「拾えていない」の両方を疑う。**

## 4. `href` の空白の不具合と、4社の seen について

指示にある「403 でない4社（イエローサブマリン・iAEON・HMV・ToysRus）が
この不具合のせいかもしれない」は、**まだ確かめていない**。次の定時 run
（JST 7:40 / 13:40 / 19:40）のあとに `ec_lottery_watch_state.json` の `seen` を
見て報告する。

**先に1つ申し送る。** この4社は `ec_lottery_sources.json`（S1）の側で、S2b の
台帳には入っていない。したがって seen が増えるとすれば **S1 の経路**であって、
今回足した S2b ではない。直した `記事リンク` は両方が使う共有の関数なので、
効くとすれば S1 側に出る。

## 5. 次にやること（18社の一覧特定）

着手した。**17社**が対象（晴れる屋2 は登録済みなので18から1減る）。
候補パス（`/` `news/` `information/` `info/` `topics/` `blog/` `shopnews/`
`news/list/`）を開いて関心リンク数を数える形で、tier A・S から見ている。

途中経過（読むだけ・まだ台帳へ足していない）:

| 社 | 所見 |

| しまむらパーク | どの道も html サイズがほぼ同じ（528KB前後）。**SPA の殻を返している疑い**。リンクの中身を見て判定が要る |

| 竜星のPAO | 全パス 11,504 バイト。同上 |

`--measure` まで通して「抽選と判定された数」で決める。
