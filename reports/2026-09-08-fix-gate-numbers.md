# 訂正: 「関門が止めるのは1,378回」は誤り。実際は145回

**画面 6社（実時刻）／上流 34社**

セッション名: api-customer
日付: 2026-09-08（JST）
区切り/依頼名: 前の報告（403と締切の関門）の数の訂正
対象: `origin/main` の台帳 3,032回

## 何を間違えたか

前の報告 [2026-09-08-403-and-expiry-gate.md](https://github.com/shinonomeheta-ai/cardbot-reports/blob/main/reports/2026-09-08-403-and-expiry-gate.md) と PR #1470 の本文に、こう書きました。

> 締切が過去で**止まる** 1,378回 ／ 締切は過去だが**発表がこれからで残る** 146回

**1,378 は関門が止める数ではありません。台帳の姿です。** metrics の指摘で気づきました。

**関門は入口に立ちます。** 止めるのは「掴んだ時点で既に締切が過ぎていた回」だけです。いま締切が過去の1,378回の大半は、**作られたときには締切が未来だった回**で、時間が経って過ぎただけです。関門があっても作られています。

書いたままだと「**台帳の45%が消える**」と読めます。実際に止まるのは **145回**です。

## 数え直し

`first_seen_at` を基準に数え直しました。

| | 回 |
| --- | --- |
| 台帳の全回 | 3,032 |
| **A いま締切が過去**（台帳の姿・関門とは無関係） | 1,524 |
| 　うち発表も過去 | 1,378 |
| 　うち発表がこれから | 146 |
| **B 掴んだ時点で締切が過去**（**関門が実際に止める数**） | **168** |
| 　うち止まる | **145** |
| 　うち守られる（掴んだ日に発表が未来） | **23** |

前の報告の数は **A** で、**B** と取り違えていました。

## metrics との差

metrics の数は 159 / 136 / 23 です。

| | 私 | metrics |
| --- | --- | --- |
| 掴んだ時点で締切が過去 | 168 | 159 |
| 止まる | 145 | 136 |
| **守られる** | **23** | **23** |

**守られる23は一致**、他の2つが9回ぶん違います。「掴んだ時点で過去」の境目の取り方の違いだと見ていますが、まだ詰めていません。桁も向きも同じなので、関門の是非には影響しません。詰める必要があれば言ってください。

## 変わらないこと

**条件も実装も変えません。** 「応募の締切が過去 かつ（発表日が無い または 発表日も過去）」を、その回を見た時刻で当てる形で正しいです。変わるのは説明の数だけです。#1470 にも同じ訂正をコメントしました。

## 同じ型を両側から踏みました

metrics 側も「発表日を**今日**と比べていた」を「**掴んだ日**と比べる」へ訂正しています。私は逆に「**いま**」の数を関門の数として書いていました。

**基準にする時点を書かずに数を出すと、両側が別の時点で数えて食い違います。** 数は時点・母数・定義の3点で言う、という決まりのうち、私は**時点**を落としていました。前の報告では母数（159 か 3,032 か）は書き分けたのに、時点（いま か 掴んだ日 か）は書いていません。
