# 2. 【急ぎ】KIDDY LAND は**名前が繋がっていません**

S6 をマージしても、**このままではカードに出ません。** マージ前にお伝えします。

```
M1g のチェーン名     KIDDY LAND        store_keys = ["KIDDY LAND"]
配布・候補の店名      キデイランド原宿店・キデイランド大阪梅田店 …（全部カタカナ）

チェーン("キデイランド大阪梅田店")            = ""   ← 本部にも
チェーン("キデイランド大阪梅田店", 支店も=True)  = ""   ← **支店にも当たらない**
```

上の調査でも、キデイランド大阪梅田店のストームエメラルダ（9/7・公式根拠あり）が
**「M1g の外」**に数えられていました。

**S6 が24件を入れても、いまの名前のままでは M1g の判定に1件も当たりません。**
「カードに出る」には、この寄せを直す必要があります。

## 直し方（ご判断ください）

* **案あ**: M1g の `KIDDY LAND` に `display_name` は変えず、
  **`extra_store_keys` へ「キデイランド」を足す**。これで前方一致（支店判定）が効き、
  支店の回は「M1g の支店」として数えられるようになります。
  **カードには出ません**（完全一致ではないため）——数え方だけが直ります。
  ただし `extra_store_keys` は**実在する店名しか採らない**ので、
  「キデイランド」ちょうどの行が無いいまは入りません。規則の緩めが要ります。
* **案い**: 別名表（`store_aliases.json`）で「キデイランド◯◯店 → KIDDY LAND」…
  **採れません**。配る側が店名を書き換えるので、利用者の応募済み・既読の鍵が動きます。
* **案う（推奨）**: **案1（KIDDY LAND の出し方）と一緒に直す。**
  「本部主体の企画は、支店の回もチェーンのカードへ寄せる」をチェーンごとに宣言する欄
  （例 `branch_rounds_are_chainwide: true` ＋ 支店名のベース `"キデイランド"`）を M1g に足し、
  カード側はそれを見て**商品ごとに畳んで**出す。§3-1-1 を壊さず、宣言した店だけに効きます。

**案う でよければ、案1 の設計案を出してから着手します。**
