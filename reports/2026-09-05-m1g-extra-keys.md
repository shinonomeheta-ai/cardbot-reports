## 2. 本部の告知をカードへ入れる → PR #1333

### 別名表では寄せませんでした（理由つき）

`store_aliases.json` で `エディオン` へ寄せると、配る側（`build_lotteries_nyuka`）が
**店名そのものを書き換える**ので、**利用者の応募済み・既読の鍵（`lot_key`）が動きます**。
足したいのは表示の枠だけなので、**M1g の欄で名指しする**形にしました
（設計書 §3-1-1-a と同じ考え方）。

### `extra_store_keys`（新設）

```
EDION.extra_store_keys = ["エディオン/トレカキャピタル", "エディオン・トレカキャピタル"]

store_keys  ['エディオン', 'トレカキャピタル']
         → ['エディオン', 'エディオン/トレカキャピタル',
            'エディオン・トレカキャピタル', 'トレカキャピタル']
```

**支店は入りません**（`トレカキャピタル広島本店（エディオン広島本店 東館B1F）` /
`トレカキャピタル横浜西口本店`）。突き合わせは完全一致のままで、緩めていません。

規則で拾えなかった理由は正規化です。`store_canon._norm` は `/` `・` を落とさないので、
`エディオン/トレカキャピタル` は `エディオン` とは別の鍵になります。

### 欄の決まり

```
書いてよい    チェーン全体の告知で、規則では拾えない綴り
書かない      支店名（表示の枠を足す欄で、支店を入れる欄ではない）
採られる条件   配布データ・名簿・候補台帳に**実在する店名**であること
             （書いても実在しなければ入れない＝幽霊の鍵を作らない）
```

### 試験（ご指示の「支店は入らないを固定」）

```
test_手で足した鍵は実在する店名だけ            実在しない名前を捨てる（合成）
test_実データ_EDIONは本部の連結名を拾い支店は拾わない
      本部の連結名2件が store_keys にある
      「本店」を含む名前・「トレカキャピタル〜店」が1つでも入ったら赤
test_手で足した鍵に支店を書いていない          欄そのものの規則（全チェーン）
```
