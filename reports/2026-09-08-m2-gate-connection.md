## ① 関門は台帳を見ているのか、AI の値を見ているのか

**台帳です。** `promote_candidate_decisions.AI昇格できるか` の実物です。

```python
if not str(c.get("store") or "") or not str(c.get("product") or ""):
    return False, "missing_identity"
```

`c` は候補（台帳）の辞書、`res生` が AI の結果です。この行は `res生` を見ていません。**同じ関数の中で AI の結果は見ているのに（`ai_status`・`observed_event_type`）、身元の2欄だけ台帳を見ている**——store-name-a の言う食い違いは実物にありました。

行を作る側（`新規行を組む` の `昇格できる欄`）は `ai値()` を通して AI の値を採るので、**関門と行の作り手が違うものを見ています**。

## ③ ⑱（本文＋辞書）と ⑲（AI）は、その 164 回と重なるか

**重なりは 11 回だけです。**

| | 回 | 意味 |
|---|---:|---|
| AI ◯ ／ ⑱ ◯ | 3 | どちらでも埋まる |
| AI ◯ ／ ⑱ × | 29 | **AI でしか埋まらない**（本文に公式名が無い・複数ある） |
| **AI × ／ ⑱ ◯** | **8** | **⑱ でしか埋まらない**（AI が商品名を返していない） |
| どちらも × | 124 | 材料に商品名が無い |

**足し算になります。** `ai値()` だけなら 32 回、⑱ を足すと **40 回**。

⑱ でしか埋まらない 8 回の例です。

```

ブックオフJR蒲田駅東口店        AI: 商品名なし   ⑱: pokemon:m6a（拡張パック「30th CELEBRATION」）
TC バトロコsatellite静岡駅前    AI: 商品名なし   ⑱: pokemon:m6a
```

### ⑱ の成果の大半は関門の外に効きます

⑱ で商品が決まる候補は **56**（締切が未来の回を持つもの）。そのうち **55 は `missing_identity` の回を持ちません**——台帳に既に商品名があり（45 件）、関門は通っている候補です。効く先は3つです。

| 効く先 | 何が変わる |
|---|---|
| **畳み（⑳）** | `set_only` のままだと「当て先が2種以上」でしか止められない。`product` に決まれば `product_id` の違いで止められる |
| **素性（(d)）** | 鍵の商品欄が `set:` でなく `id:` になる。書き方違いが寄る（案E＋凍結欄の後） |
| **札（判断③）** | 「商品未特定」の札が 56 件ぶん減る |

### 追加で要る配線が1つあります

**⑱ 由来の 8 回を関門に通すとき、行の商品名をどこから取るか**が決まっていません。`昇格できる欄` は `ai値()` から採るので、AI が商品名を返していない 8 回は**行の商品名が空になります**。

**M2 の正式名（`title`）を渡す配線が要ります。** 新しく作る行なので `event_id` は動きません（誕生時に決まる）。store-name-a の「AI の商品名で行を作れば正しい ID が最初から付く」と同じ形です。

## 今日の実装（PR #1472・⑱⑳）

| | 実測 |
|---|---|
| ⑱ 材料の本文にも辞書を当てる | 締切が未来の回を持つ候補で **56 件**が `set_only` / `empty` → `product`。本文に公式名が1つだけのときだけ採る。**本文からゲームは当てない**（NIKKE がユニアリとヴァイスの両方にあるため） |

**実装直後に不具合を1つ踏みました。** `fold_blocked` に表示名（「ポケモンカード」）が渡って関門が1件も効かず、実データで 131→131 のままでした。`game_identity` で正準化して直し、試験で固定しています。**実装した直後に実データで効きを測ったので見つかりました。**
