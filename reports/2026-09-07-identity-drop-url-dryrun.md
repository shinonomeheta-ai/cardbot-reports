## 1. 4-1 で何が起きていたか

ブックオフ川崎モアーズ店・締切 9/13 の応募回が、台帳に**4つ**あった。

| 応募回 | 持ち主の案件 | 素性（店｜ゲーム｜商品｜種別｜**URL**） |
| --- | --- | --- |
| `rnd_27a4f888` | `evt_ad3c0b3a` | …｜`30thcelebration`｜抽選｜**（空）** |
| `rnd_987692d7` | `evt_8a8c8c6a` | …｜`30thcelebration`｜抽選｜**X の投稿URL** |
| `rnd_3096571f` | `evt_2422f170` | …｜`ポケモンカード30thcelebrationbox`｜抽選｜X の投稿URL |
| `rnd_65df3e58` | `evt_aef67bda` | …｜`…mega拡張パック30thcelebration1boxおひとり様…` |

**上の2つは、店もゲームも商品も種別も同じ**（`30thcelebration`）で、**違うのは URL だけ**。
それだけで別の案件として2つ発番されていた。

配布の3行は、いずれも**自分の案件とは別の案件の応募回**を持っていた。

    行「30th CELEBRATION」        → rnd_3096571f（持ち主は別案件）
    行「…1BOX（おひとり様…」      → rnd_27a4f888（持ち主は別案件）
    行「ポケモンカード 30th…BOX」  → rnd_987692d7（持ち主は別案件）

### なぜそうなるか

`event_id` は「店｜ゲーム｜商品｜種別｜**URL**」で決まる。同じ抽選でも
**根拠のURLが変わると別の案件**になる。

    1. URL 空で集まる      → evt_ad3c0b3a → rnd_27a4f888 を発番
    2. X の投稿URLが付く   → evt_8a8c8c6a → **別の応募回** rnd_987692d7 を発番
    3. 行に残る古い round_id は「持ち主が違う」ので剥がされる
    4. 剥がした行に、また別の round_id を刻む

これが毎回繰り返され、行と台帳の対応が入れ替わり続ける。
`materialize_event_ids` は「台帳は答えを持っているのに刻まれていない」
（`台帳の一致`）と判定し、**中途半端を残さないために取引ごと巻き戻す**。
関門としては正しい。

**候補として挙げていた「保存の途中で畳まれている」「人手補正が戻している」は
どちらも外れ**で、4つ目（素性にURLが入っていること）だった。

    行数 311
    registry   index_keys 3,026 ／ added_keys 159 ／ unresolved 0
               resolved 243 → 311      ← 311行すべてが案件へ解決する
    残る未刻印 68（内訳: 未登録 67 ／ 台帳の一致 1）
    取引を止める行  2 → 1

`未登録` は「発番すれば済む」ので取引を止めない（#1405 で分けた）。

**`unresolved 0`** が大きい。案E なしでは解決しない行が残るが、案E では
**配布の全行が案件に結びつく**。

## 3. ただし巻き戻りは 0 にならない

**1行だけ残る。**

    MINT GAMES池袋店
      ポケモンカードゲーム MEGA 拡張パック「30th CELEBRATION」1BOX（7,200円税込・お渡し 9/1…
      締切 2026-09-13T21:00   why: 台帳の一致

川崎モアーズの2行は**消えた**（案E が効いた）。残る1行は別の店で、同じ症状。
**1行でも残れば取引全体が戻る**ので、案E をマージしても**巻き戻りは続く**。

したがって「マージ後に `ai_not_run` が 290 から減る」は、**この1行を直すまで
起きない**見込み。

## 4. 判断をお願いします

| | 内容 | 効き |
| --- | --- | --- |
| **A** | 案E をマージし、残る1行は別途 | 原因の8割が消える・`unresolved 0`。ただし巻き戻りは続く |
| **B** | 残る1行を先に調べ、案E と一緒に直してマージ | 巻き戻りが止まるまで `ai_not_run` は増え続ける |
| **C** | 案E をマージし、**同時に**残る1行を調べる | A の効果を先に入れつつ、止まるまでを短くする |

**私の見立ては C。** 案E は単独で価値があり（`unresolved 0`・200組の統合・
redirect 191件の不要化）、残る1行は案E の有無にかかわらず存在する別の問題。

**ただし、マージしても `ai_not_run` はすぐには減りません。** ご指示の
「マージ後に確認する3つ」のうち、実際に確かめられるのは

  * 巻き戻りが消えること     → **消えない**（1行残る）
  * `ai_not_run` が減ること   → **減らない**（巻き戻るため）
  * 227件が台帳に入ること     → **入らない**（同上）

で、3つとも「残る1行を直すまで達成しない」ことになります。
それを承知のうえで A/C を選ぶか、B で待つかの判断をお願いします。

## 5. 私の以前の誤りの訂正

「案E は `no_event_id` 226 行に効かない」と報告した（根拠は `ambiguous: 0`）。
**誤り。** いま起きているのは `ambiguous` ではなく「**同じ抽選が複数の案件に
割れている**」で、案E の対象そのものだった。

`ambiguous`（同じ案件・同じ締切の応募回が2つ以上）が0件であることと、
案E が効くかどうかは**別の話**だった。数字は正しく読んだが、**その数字が
何を意味するかを取り違えた**。
