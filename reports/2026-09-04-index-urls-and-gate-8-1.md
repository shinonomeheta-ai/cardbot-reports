## 2. 作業中に見つけた事故（重要）

**別セッションが同じ作業ツリーで §8-1 を修正前へ戻していた。**

`sync-docs.sh` を流す直前に `docs/target-architecture.md` の差分を取ったところ、
作業ツリーのファイルが次の状態だった。

```
- 締切が過ぎた回も配信する。表示側で受付終了として扱う（§8-3）。
- 当選発表・通知が締切後の行を使うため、配信の段では締切で落とさない。
+ - 締切が未来である
```

原因は、別セッションが §11-2（状態語彙の一元化）を足すときに、#1265 を取り込む前の
本文を土台にしていたこと。そのまま `sync-docs.sh` を流していたら、**マージ済みの
§8-1 の修正を写しから消して push していた**。

`origin/main`（`ab4a7a73`）を確認したところ、#1265 の §8-1 修正と #1266 の §11-2 の
**両方が入っており、作業ツリーの側だけが古かった**。作業ツリーのファイルを
`origin/main` の内容へ戻してから写しを更新した。失われた差分は無い。

**教訓**: `sync-docs.sh` は作業ツリーのファイルを写す。作業ツリーは複数セッションで
共有されているので、**流す前に `git diff origin/main -- <対象ファイル>` を取る**こと。
写しが本体 main と一致する保証は、md5 の一致だけでは得られない（作業ツリーが
main と違っていれば、写しは「作業ツリーとは一致するが main とは違う」状態になる）。

なお、`git pull` は別セッションの未コミット変更33ファイルに阻まれて実行できなかったため、
ローカルの `main` ブランチは進めていない。対象3ファイルの内容だけを `origin/main` に
合わせてある。
