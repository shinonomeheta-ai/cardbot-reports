# 2. 罠を記録しました → PR #1388（docs だけ）

`docs/renaming-procedure.md` の「直すときの道具（既知の罠）」へ足しました。

> **`store_sites.json` へホストを足すと、別の名義から取り上げることがある。**
> 登録は増やすだけではない。`store_sites.json` は**1名義1URL**なので、
> 同じホストを2つの登録名へ持たせられない。あとから足した名義がそのホストの
> 持ち主になり、**前から持っていた（あるいは「誰のものでもない」ことで使えていた）
> 名義が使えなくなる。**

実測もそのまま残しました。

```
shop.joshin.co.jp を「ジョーシン（アプリ）」で登録
   → 店「Joshin」が この応募先を own source として採れなくなった
   （test_own_source_apply_url が 期待 …/lottery/1 に対して ''）
   登録前は「誰のものでもない」ので採れていた
```

あわせて2点。

* 効くのは `url_quality.host_belongs_to`（own source の判定・応募URLの採用）。
  **足す前に、他の名義が使っていないか確かめる**
* `host_belongs_to` は**登録した名義から見た True** しか教えない。
  **反対側から見ると False へ変わっていることがある**——
  片側だけ見て「増えた」と言わない（**私が前便でやりました**）
* 1名義に複数URL（配列）は `store_hosts()` だけは受けられるが、
  **他の読み手十数か所が文字列前提**。広げるならその点検とセットで（＝案2）
