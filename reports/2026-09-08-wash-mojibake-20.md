## 4. cardmax の原因と修正（#1453）

このページは文字コードを**正しく宣言しています**。

```
ヘッダー  Content-Type: text/html; charset=EUC-JP
メタ      <meta charset="euc-jp">
宣言された文字コード() → 'euc_jp'
```

判定は合っていました。壊れていたのは**その先**です。`decode_html` は宣言を先頭に候補を順に**厳密に**読み、全部失敗したら最後に UTF-8 の `replace` へ倒します。壊れたバイトが6個あるだけで EUC-JP の厳密な読みが例外になり、UTF-8 に着地していました。

```
euc_jp  replace →      6 置換文字（本文は読める）
utf-8   replace → 21,455 置換文字（丸ごと化ける）  ← これを返していた
```

**#1437 で判定は1か所に寄せましたが、判定の後の落とし先が UTF-8 決め打ちのままでした。** 宣言があるときだけ、その文字コードの `replace` へ倒すようにしました。

```
cardmax  21,455 → 6 置換文字
題名     読めない → トレーディングカードショップCARDMAX
HMV      0 → 0（変わらない）
```

**宣言が無いときは推測しません。** ここは一度間違えました。「置換文字がいちばん少ない読み方を採る」という一般則を先に書いたところ、宣言の無い EUC-JP のバイト列を **cp932 が置換文字ゼロで読んで勝ちました**（中身は化けたまま）。cp932 はほぼどんなバイト列も例外なく読めるので、傷の少なさでは選べません。試験にその形で残しています。

試験は `test_html_charset` 17件 OK（3件追加）。周辺400件で新しい赤はありません（赤2件は変更を外しても出る main 由来）。
