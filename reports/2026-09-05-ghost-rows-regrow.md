## 判断していただきたいこと

### 案A: 幽霊の行を「統合済み」にする（推奨）

台帳には `status` と `merged_into` があり、`targets()` は既に
`closed / merged / excluded` を除外しています。**台帳が持っている仕組みです。**

```python
if row.get("status") in ("closed", "merged", "excluded"):
    continue
```

17件の幽霊の行を `status="merged"`, `merged_into=<本物の鍵>` にすれば、
探索の対象から外れ、二重登録も止まります。

- 利点: 台帳の設計どおり。店名を書き換えないので、`observe()` の
  「先に書いた者が勝つ」構造に触らない
- 欠点: **台帳の行が17件動きます。** 前回「1（observe が良い表記を採る）は
  台帳の店名が動くのでいまはやらない」とご判断された範囲に近い
- 17件のうち何件が本当に同じ店かは、1件ずつ根拠を示します
  （`ポケモンセンター` と `ポケモンセンターオンライン` は**別**かもしれません）

### 案B: `targets()` で「同じ店の別綴りが登録済みなら対象にしない」

探索の側で `SX._norm` の一致も見て、既に登録があれば対象から外す。

- 利点: 台帳を触らない。1か所の修正で17件とも止まる
- 欠点: **緩い一致を判定へ戻すことになります。** 段2 で外したばかりの
  `_norm` を、別の場所で使い直す形。「探索の対象を決めるだけで、
  権限は与えない」ので配布への影響はありませんが、規則が2つに戻ります

### 案C: 誤登録2件のうち1件（`福福秋葉原店 → @fukufuku_yg`）を外す

案A・案Bとは別に、既に付いてしまった誤りを外すか。
`萬屋紫波店 → @yorozuya_shiwa` は正しいので残します。

### こちらの推奨

**案B → 案A の順**を推奨します。案B は台帳を触らずに出血を止められるので先に。
案A は「どの行とどの行が同じ店か」の判断が17件ぶん要るので、
止血してから1件ずつ根拠を出したほうが安全です。案C は案Bと同時に。
