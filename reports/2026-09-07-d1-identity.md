### 4. 登録用スクリプト: PR #1391 `roundup_store_discovery.py`

```
py roundup_store_discovery.py --url <一覧ページ>            # 発見して候補 JSON を書く（登録しない）
py roundup_store_discovery.py --url <一覧ページ> --verify   # 新規候補の X 表示名も取る（tweet-result）
py roundup_store_discovery.py --apply --approved <JSON>     # 人が承認した行だけ登録
```

- URL は引数（複数可・既定値なし）。弾が変わったら URL を差し替えるだけ
- 一覧ページから取るのは **店名と、同じ行にある X のリンクだけ**（商品・締切・期間は取らない。§0-1 原則 2）。相場の行や「1BOX」の行は飛ばす。まとめ自身の X（`CURATION_X_HANDLES`）は除く
- **最初の段は店名でなく X の口で引く**: 行の handle が `store_x_accounts.json` に登録済みなら、その持ち主が既存の店（`alias_by_handle`）。店名の正規化で見つかれば `known`。どちらも無ければ `new`。前回の 58 件で言えば 43 件がこの段で既存店に着く
- `--apply` は承認ファイルの行だけを登録する。handle が別の店に登録済みなら飛ばす（口を取り上げない。#1387 のジョーシンの罠と同じ守り）
- 試験 9 件（`test_roundup_store_discovery.py`）。実データは読まない

### 5. 設計書 §2 の追記（PR #1391 に同梱）

§2-2 に「まとめからの発見の最初の段は『店名』ではなく『X の口』で引く」を追加。順序は (1) 行の X handle → 登録済みの口 → 既存の店名、(2) 店名の正規化 → 既存の店名、(3) どちらも無ければ新規候補（人の承認へ）。道具名も書いた。
