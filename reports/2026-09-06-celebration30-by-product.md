main と #1351 の枝で、同じ物差しで測り比べました。

```
候補側で #1351 により M1g に当たるようになる  6件（ご指示の6店ちょうど）
   Bee本舗    ← Bee本舗各店（大阪本店・秋葉原店・…）

   晴れる屋2   ← 晴れる屋2各店（店舗）
   WonderGOO ← WonderGOO・新星堂・Ganryu各店
   GIRAFULL  ← ジラフル各店（なんば店・オタロード店・…）

配布側で増える／減る   0件
```

**配布側が0なのは、この6店の回がまだ配布に出ていないから**です。カードの枠は
常に出ますが、**「受付中◯件」になるのは配布行が出てからです**（#1349 の関門次第・
ci が確認）。

### CI

```
python test   main の失敗4件 と **完全一致**（PR固有の赤 0）
build         赤4件だが、`origin/main` のチェックアウトでも同じ4件が落ちる
                ページを辿ると全件を重複なく取れる
                実データの候補・応募回が欠けずに行になる
                health は行の件数と根拠の件数を混同しない
                [P1] 成功の health は台帳の実際の数と合っていること
```

**#1351 は途中で1度、競合でCIが起動しませんでした**（巡回が `store_x_accounts.json` を
書き換えたため）。main を取り込み直し、`shadow_url_owner.json` も作り直しています。
