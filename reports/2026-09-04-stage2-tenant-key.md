## 1. やったこと

`normStoreName()` は `通販` `各店` `店舗` `ショップ` `トレカ` を**語ごと**落とします。
投稿者の照合には都合がよいのですが、権限の照合に使うと別の店の登録が効きます。

```
normStoreName("カードボックス通販") === normStoreName("カードボックス")
normStoreName("ドラゴンスター通販") === normStoreName("ドラゴンスター")
```

2026-08-16 に受付基盤（`store_platforms.json`）の側だけ [P1] として塞いだ穴が、
**Xアカウント表・店サイト表に残っていました**。衝突した鍵は「どちらとも決めない」で
まるごと落とすので、衝突していた店は**どちらも配れていません**でした。

8経路（Python 5・JS 3）の鍵を `tenantKey` へ寄せました。


チェーンの束ね（`chainKey`）は緩く当ててよい場所で、用途が違います。

## 3. 途中で見つけたこと: 表の鍵そのものが壊れていた

**`store_x_accounts.json` の鍵は店の表示名のはずですが、36行は
`normStoreName()` の出力そのものでした。** 正規化した結果を店名として書き戻した形です。

```
36行の内訳
  tenantKey が吸収する（空白・大小文字だけ）  20
  語ごと落ちている（tenantKey では戻らない）  16
```

判定は「その handle のXプロフィール表示名を `normStoreName()` に通すと、
表の鍵とぴったり一致する」で行いました。実例:

```
表の鍵 'ゲームプラスアルファ'   @plus_alpha_anms   実際の表示名 'ゲームショップ プラスアルファ'
表の鍵 '福福秋葉原店'           @fukufuku_toreka   実際の表示名 '福福トレカ秋葉原店'
表の鍵 'どみなり屋'             @dominariya        実際の表示名 'カードゲームショップどみなり屋…'
表の鍵 'カードきんぐ神戸三宮本店' @cardking_kobe    実際の表示名 'トレカショップ カードきんぐ 神戸三宮本店'
表の鍵 'アトラ豊田店'           @atola0315         実際の表示名 'トレカショップアトラ　豊田店'
```

**これは #1276 で直した出口の不具合と同じ型です。** 向こうは「正規化した名前で
登録しようとする」、こちらは「正規化した名前が既に登録されている」。
どちらも `正規化した値を店名として持ち回る` が根にあります。

さらに、店の台帳には**壊れた名前と正しい名前が別々の行として両方あります**。

```
どみなり屋                  canonical=どみなり屋                  x_candidates=[]
カードゲームショップどみなり屋 canonical=カードゲームショップどみなり屋 x_candidates=['dominariya']
カードクラクラ               canonical=カードクラクラ               x_candidates=[]
カードショップクラクラ        canonical=カードショップクラクラ        x_candidates=[]
福福秋葉原店                canonical=福福秋葉原店                x_candidates=[]
福福トレカ秋葉原店           canonical=福福トレカ秋葉原店           x_candidates=[]
```

壊れた名前が**幽霊の店の行**を作っています。
