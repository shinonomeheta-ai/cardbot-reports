# 2. 入れ方 — **刻み直さずに、同じ効きにしました**

ご指示は「指紋を刻み直す」でしたが、**払った答えの `input_fingerprint` は
書き換えない**形にしました。理由を書きます。

## なぜ書き換えないか

**書ける場所ではありません。** `fill_round_methods` が走る `update-data` /
`nyuka-watch` は `shadow_candidate_ai.json` をコミットしません（払った記録の
持ち主は `candidate-ai-review` 側です）。ここで書き換えても捨てられ、
台帳だけが進んだねじれが残ります。

**記録が消えます。** `input_fingerprint` は「どの材料に対して答えたか」の証拠です。
上書きすると、その答えが実際に何を見て出たものかが分からなくなります。

## 代わりに、読む側で判定します

```
厳密一致に加えて、**その答え自身が書かせた値だけが違う**場合も
「いまの材料に対する答え」とみなす
```

**効きは刻み直しと同じで、記録は失いません。**

判定は1か所（`candidate_ai_contract.同じ材料か()`）。使う側は3つです。

```
check_candidates_ai.対象()            もう一度聞くか（**課金の判断**）
promote_candidate_decisions.ai結果()   値を採ってよいか
candidate_ai_ledger.classify()        新しいか古いか（health の数）
```

## ご指定の条件は守っています

> 刻み直すのは「その AI の答えそのものを書いた」場合だけ。
> 人が直した値・別の経路で入った値は刻み直さない。

戻すのは、**いまの値がその答えの観測値と一字一句同じ**で、かつ `checks` が
その欄を `confirmed` / `conflict` と判定していた欄だけです
（`apply_start` / `apply_end` / `result_date`）。

```
AIの答えと同じ値      戻す（同じ材料とみなす）
人が直した違う値      戻さない → **聞き直す**
判定が missing の欄   戻さない → **聞き直す**
AI由来でない欄が動いた  戻さない → **聞き直す**（商品名が変わった等）
```

試験で4通りとも押さえています。

# 3. もう1つ直しました（起こした回が1日止まる）

起こしたばかりの正式回には、まだAIの答えがありません（答えは起こす前の暫定回に
紐づいたまま残ります）。昇格のAIレーンは「AI審査済みか」を見るので、
**そのままだと締切を読めた回が「AI未実行」で1日止まります。**

`promoted_from` をたどって、起こす前の答えを**関門の判断にだけ**使う形にしました
（`AIレーンの答え()`）。**値は採りません**——値の採用は指紋の関門を通ったものだけで、
起こし直した回では通らないので、台帳に入った締切が使われます。

これが無いと配布行の増加は **0** でした（実測）。
