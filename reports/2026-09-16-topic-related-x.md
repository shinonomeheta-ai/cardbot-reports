## 結論

似たX話題を「捨てるだけ」にしていて、関連へ足していなかった。加えて、`related_posts` が1件でもあると再収集しなかった。9月11日のトイザらス30th（`5aaf3de43c11aad4`）は 2026-09-12 に1件集めたあと、打ち切られたままである。

直しは `fix/topic-related-x`（PR #1592）。Cursor の作業フォルダは `D:\cardbot` のまま動かしていない。失敗した SEO 用フォルダ `worktrees/topic-seo` と枝 `feat/topic-seo` は捨てた（origin/main からの固有コミット0）。有料の x_search は叩いていない。投稿は捏造していない。`D:\cardbot` の現行枝 `fix-x-next-always-assemble` には混ぜていない。

9月11日の画面が今すぐ15件になるわけではない。履歴に捨てた兄弟URLは残っていなかった。次の収集便で、1件の話題を集め直す。

## 何が壊れていたか

機構は2段ある。どちらも空振りしていた。

### 1. 似た話題を捨てて、URLを捨てていた

Grok は同じ出来事の別投稿も返す。`build_news.py` は未確認同士で見出しの共通部分が6文字以上なら **追加せず `continue`** していた。捨てた側の `source_url` は `related_posts` に足していなかった。

「似ているやつを、その関連したXとして取る」は、この捨てる処理の裏にあるはずだった。実装は捨てるだけだった。

### 2. 1件でも集まると再収集しない

`collect_related_posts` の対象は `not it.get("related_posts")` だけ。1件入った話題は二度と対象にならない。

9月11日の実データ:

| 項目 | 値 |
| --- | --- |
| id | `5aaf3de43c11aad4` |
| 見出し | トイザらス30thポケカ 本人確認で社員証・学生証併用を許可 |
| 公開日 | 2026-09-11 |
| 関連X | **1件** |
| 収集日 | 2026-09-12 |

同じ「トイザらス」でも `6110c8978eb426e8`（厳格抽選・ゲリラ販売、8件）は **別の出来事**。`topicsLookSame` は false。混ぜない。

### 3. 本番の上限が10件

コード既定の `NEWS_RELATED_MAX` は20。GitHub 変数は **10** だった。10件止まりの話題が8件あるのはこれ。

画面の `foldSimilarTopics` も、同じ波を畳むとき投稿を寄せていなかった。今の9月11日には兄弟が残っていないので、表示だけのマージでは1件のまま。

根拠: [2026-09-16-topic-related-x.json](https://raw.githubusercontent.com/shinonomeheta-ai/cardbot-reports/main/reports/data/2026-09-16-topic-related-x.json)
