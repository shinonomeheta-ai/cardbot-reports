## 2. 解決の規則（`resolve`・推測しない）

```
1. 括弧の中を外す（条件・内訳）。数字に挟まれた「/」（9/11）は区切りにしない
2. 「／」「/」「｜」で割る（「・」は割らない＝エーフィ・ブラッキー）
3. 各片: 別名表の完全一致 → product
         公式の名前が丸ごと含まれる（長い一致が勝つ・飲み込まれるものは落とす）→ product、2つ以上 → multi
         弾の名前が含まれる → set_only（商品は決めない・判断②）
         名前の方が短い（「30th」「ORIGINAL」）→ 弾と商品の両方で「含むもの」を集め、全部が1つの弾を指すとき
           だけ set_only。「ORIGINAL」は COLLECTION（弾あり）と DUEL SET 3種（弾なし）に当たるので unknown
4. 括弧の内訳: 外の名前だけで商品が決まっていなければ、「外＋内訳」が**全部別の商品**に当たるときだけ product_ids へ
5. 販売単位: 括弧の外の「1BOX」「5パック」。上限の言い方（お一人様1BOX・3BOXまで）は数量ではない
```

## 3. 仮定（`docs/assumptions.md` に記録）

- 弾（set）は **pack 形態の商品の芯**から作る。デッキ・特別セット・カードセットは芯に弾の名前を含めばその弾へ（長い一致）。含まなければ弾なし（`set_id` 空）。
- 公式に無い名簿の名前は `legacy` の弾として残す（消すと `lot_key` が動く）。実測 21: onepiece 11（2024年以前のブースター。fixture がブースター2頁ぶんのため。`build --fetch` は頁が空になるまで読むので本番では減る）・unionarena 5・pokemon 2（「スターターセットex」「30th CELEBRATION カードセット (9種セット)」）・dragonball 2（「Fusion World」「フュージョンワールド」）・yugioh 1。
- ポケモンの `product_id` は slug。同じ slug に複数商品が並ぶときだけ名前の正規化を付ける。公式が後から同じ slug へ商品を足すと先の ID が変わる——実測ではこの2例だけ。起きたら別名表で吸収。
- **短い名前から商品へは寄せない。** 「BRIGHTNESS」は弾 BRIGHTNESS OF HOPE の set_only（その弾に商品が1つでも）。→ 判断⑦。
- `resolve()` の別名表は公式名そのままだけ（by=official）。人・AI の別名は段2以降の育成キューから。
- 文字の正規化は `event_identity.norm`（identity と同じ並び・§11-1-1）。
