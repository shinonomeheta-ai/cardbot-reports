# 1. 案1（案う）の設計案

## 1-1. 欄の形（M1g・`golden_chains.json`）

```json
"chain_campaign": {
  "enabled": true,
  "branch_name_base": "キデイランド",
  "evidence": "LivePocket の各イベントに「キデイランドの複数店舗での重複応募は無効」とあり、
               チェーン横断で応募を数えている。二子玉川店と吉祥寺店のデュエマは商品・
               エントリー期間・当選発表・引換期間がすべて同じ（2026-09-07 実測）",
  "confirmed": "2026-09-07"
}
```

* **宣言した店にだけ効きます。** 書いていないチェーンは今までどおり
  「支店の回はカードに入れない」（§3-1-1）のままです
* `branch_name_base` は**支店名の頭**。`golden_chain_index` の前方一致に使います。
  KIDDY LAND は `canonical_name` が英字で店名がカタカナなので、**この欄が無いと当たりません**
* `evidence` は必須にします（**空なら試験が落ちる**）。「本部主体」は
  観測で言えることなので、**何を見てそう言ったか**を残します

## 1-2. 畳み方

```
寄せる      chain_campaign.enabled のチェーンは、支店の回もそのチェーンの回として数える
           （判定は golden_chain_index.チェーン(..., 支店も=True) の1本・U）
畳む単位    (商品, 応募の締切) —— 商品ごとに1件。締切が違えば別の件
数える      カードの「受付中 n件」の n は**畳んだあとの件数**（店舗の数ではない）
残り時間    畳んだ中でいちばん近い締切
```

**なぜ「商品ごと」か**: 利用者が知りたいのは「KIDDY LAND で 30th の抽選をやっている」
であって、店舗の数ではないため（本人指示）。実測でも 30th は9店舗・同じ期間で、
畳めば**1件**になります。

**締切が店舗でずれることがあります**（原宿だけ 9/8・他は 9/7）。
このときは**遅いほうを畳んだ件の締切**にし、シートで店舗ごとの締切を出します
——早いほうに合わせると、まだ応募できる店を「終了」に見せてしまうためです。

## 1-5. カードへ集約した回は、全店舗の行から外す（2026-09-07 追記）

ci 宛の連絡から回ってきた条件です。

> 案うが入るまでは、原宿店の行は全店舗の行に出る。案うが入れば、カードにも集約される。
> 両方に出るのは「重複させない」原則に反するので、案うの実装で「カードに集約したら
> 全店舗の行からは外す」形にする必要がある。

**設計へ入れます。** いまの振り分けは `splitByGolden` の1か所で、

```
cardChainOf(店) が非 null   → cards（カードへ寄せる。行リストに出さない）
それ以外                   → rest（全店舗の行）
```

という形です。`chain_campaign.enabled` のチェーンでは **`cardChainOf` が支店名でも
非 null を返す**ようにすれば、**同じ1か所の判定で自動的に行リストから外れます**。
新しい除外規則を別に足しません（重複の排除を2か所に書かない）。

```
案うが入る前   キデイランド原宿店の行 → 全店舗の行に出る（いまの状態）
案うが入った後  同じ行 → カードへ集約され、全店舗の行からは消える
```

**切り替えはチェーン単位**なので、宣言していない店の見え方は変わりません。
