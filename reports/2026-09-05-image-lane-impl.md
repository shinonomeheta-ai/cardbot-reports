### 1. a〜d の実装: PR #1303

https://github.com/shinonomeheta-ai/cardbot/pull/1303（枝 `fix/image-material-lane`・4 commit＋直し 1）

#### a. 画像URLを全経路で保存 —— 真因は「投入側が渡していない」

| 経路 | 画像の扱い（直す前） |
|---|---|
| 埋め込みタイムライン（`official_x_intake`・nyuka-watch） | `p.get("media")` を渡す。**保存される** |
| tweet-result（`backfill_x_post_media`・手動のみ） | `photos[]` から取る。**保存される** |
| **X API**（`ingest_official_x`・List と根拠の lookup） | client（`_画像を貼る`）は `media_urls` を付けている。**投入側 `取り込む` が `link_urls` しか渡していない**。台帳は `None` を「取っていない」と読んで前の値（空）を残す → **全部空** |

09-04 の 200 件はこの API 経路（`candidate-ai-review.yml` の根拠 lookup。`author_id` が入っているのが印）。
さらに、補充スクリプト `backfill_x_post_media` は「リンクがあれば済んだ扱い」で、API 経路の投稿（`link_urls` に
画像の `/photo/` リンクが並ぶ）を **285 件飛ばしていた**。しかもどの workflow にも配線されていなかった。

直し:
- `ingest_official_x.取り込む` に `media_urls` / `video_urls` を渡す（欄が無ければ None＝前の値を消さない）。要約に「うち画像あり N」を出し、次の巡回で API が画像を返しているか分かるようにした
- `backfill_x_post_media.足りない投稿`: 「画像が無く、リンクが画像を指しているなら対象」へ
- `official-x-ingest.yml` に補充 step（tweet-result・鍵不要・`--max 150 --sleep 1`・落ちても後続へ）。285 件は 2 走行で埋まる

#### b. 聞き方に「添付画像は告知の一部として読む」

- `user_prompt(…, 画像枚数=)`: 「**URLは開けません。** 上の `本文:` と、この依頼に添えた添付画像（N枚）に載っている範囲だけで確かめる」＋「画像に書かれている値は observed_* に入れる。応募期間と購入期間・当選連絡の期限を取り違えない」。**枚数 0 なら従来と 1 字も変わらない**
- 枚数は request に実際に積む数（`MAX_IMAGES`=2 まで）と揃える。`prompts_for` の形は変えない（試験が 2 引数で差し替えているため中で `images_for` を引く）
- SYSTEM は変えない。1 文伸ばすと画像なし 20 件の最悪費用が 1 走行の上限 $1.10 を $0.005 超えて 19 件に減った（試験で捕まった）。画像の話は画像を添えた回だけ長くなる
- **`PROMPT_VERSION` 11・`PROMPT_COMPAT` 11**。既存の欄（締切・受付開始・発表）への問いが変わるので、決まり（`test_prompt_compat`）どおり保存済みの答え 1,169 件は全件が聞き直しになる。画像を読まずに「無し」と答えた回を使い回さないため。**費用は Sonnet 5 で 1 回 $0.015〜0.02、全件で $20 前後**（1 走行の上限 $1.10 のまま日をまたいで進む）。**ここは判断が要る**（下）

#### c. 日付の並び

`observed_date_order_conflicts` を `merge_answer` に足した。受付開始 ≤ 締切 ≤ 当選発表（日付の部分だけ・同日は許す）。
壊れていれば該当欄を conflict・`semantic_status` を conflict・理由に `date_conflict`。試験は実測の外れ 3 回の型そのもの。

#### d. 設計書

`docs/target-architecture.md` §1-2・§6-4 に追記（画像は投稿本文の一部／根拠として保存／聞き方に枚数と扱いを明記／
§6-4 の禁止に当たらない理由／画像を読んだ値は §6-3 の日付整合で検査）。

#### 試験
