## 指示と実装の食い違い（2点・いずれも実装側で判断を変えた）

### ①「`official_accounts()` を正規化した鍵の表を返す1本にする」→ そのままでは表示名が壊れる

`official_accounts()` の戻り値を**表示名として使っている読み手が4つ**ある。

| 読み手 | 使い方 |
|---|---|
| `official_announce.store_handles` | `out[k] = (店, ハンドル)` — 通知に出す店名 |
| `official_x_intake.targets` | `out[handle] = 店` — 取り込み先の店名 |
| `store_x_watch.公式Xの表` | 同じ handle を持つ店から代表名を選ぶ |
| `store_ledger.build` | 公開台帳 `stores.json` の行の名前 |

ここの鍵を正規化に変えると、利用者に見える店名が `bigmagic秋葉原店` のような
正規化後の文字列になる。

**そこで「1本にする」の中身を、`official_accounts()` の置き換えではなく
`official_handle_map()` / `official_handle()` の新設にした。** 正規化した鍵の
索引を作る場所は1か所だけ、という指示の狙いはそのまま満たす。
`official_accounts()` は「台帳を安全に読む（収集元を落とす）」という
従来の役割のまま残す。

### ②「衝突する鍵は落とす」→ そのままだと15の店名が引けなくなる

指示どおり衝突鍵を落とす形で実装して実測したところ、**いま正しく引けている
15の店名が引けなくなった**。

```
カードラボ / カードラボ店舗 / ドラゴンスター / ドラゴンスター各店 /
ドラゴンスター通販 / ヤマダデンキ / TSUTAYA大垣店 ほか（大文字小文字違いの重複行）
```

`_norm()` は `通販` `店舗` `各店` を語ごと落とすので、別の登録が同じ鍵になる。

**そこで「登録名そのものの完全一致を先に見る」段を足した。** 行の店名が
台帳の登録名と1文字も違わないなら、どの登録を指しているかは曖昧ではない。
曖昧なのは「正規化しないと当たらない、かつ衝突している」場合だけで、
そこは指示どおり空を返す（どちらの店とも決めない）。

この2段にしたことで、引けなくなるのは `ドラゴンスター各店`（配布4行）**1件だけ**
になった。
