## 1. 429 と 0件 を分ける（今夜の1つ）

`search_any(query, timeout, 十分か, 診断)` に `診断` を足しました。検索ごとに次を積みます。**記録するだけで、進み方は変えません。**

```
{"engine": "Brave", "status": "rate_limited", "chars": 0, "detail": "HTTP Error 429: …"}

status は ok / empty / rate_limited / forbidden / timeout / error
判定は `_断られ方()` 1本（429 を error に混ぜない）
```

`ec_lottery_watch.検索で一覧` が host ごとに診断を残し、429 のときは標準エラーへ「0件と同じに見せない」と出します。

### 実物での確認（イエローサブマリン）

```
{"yellowsubmarine.co.jp": [
  {"engine": "Yahoo",    "status": "rate_limited", "chars": 0,     "detail": "HTTP Error 429"},
  {"engine": "DDG",      "status": "empty",        "chars": 14196},
  {"engine": "DDG lite", "status": "empty",        "chars": 14195},
  {"engine": "Brave",    "status": "rate_limited", "chars": 0,     "detail": "HTTP Error 429"}]}
```

**4つのうち2つが 429 でした。** 前報で「サイトに抽選記事が無い可能性」と書いた 0件は、半分が「叩けていない」でした。ご指摘のとおり、`seen 0` の分析と `no_excerpt` の分類も同じ汚染を受けている可能性があります。

試験は `test_discover_official_x_web` 32件（足したのは3件: 429 と empty を分けること・語彙・診断を渡さなくても動くこと）。

## 2. a. 締切が実時刻で過ぎている行

いまの本番（測定 2026-09-07 21:26 JST）。

| | 社 | 行 |
| --- | --- | --- |
| 画面（暦日判定・いまの API） | 8 | 15 |
| うち実時刻で締切を過ぎている | 2 | **3** |
| **実時刻で数え直した画面** | **7** | 12 |

過ぎている3行:

```
晴れる屋2 通販                 2026-09-07T18:00  30th CELEBRATION 拡張パック
晴れる屋2 通販                 2026-09-07T18:00  30th CELEBRATION プレミアムデッキセット
WonderGOO・新星堂・Ganryu各店   2026-09-07T20:59  30th CELEBRATION 拡張パック
```

**WonderGOO は社ごと落ちます**（受付中の行がこの1件だけ）。晴れる屋2 は各店の2件（9/12 締切）が残るので社としては残ります。

x-intake の表にあった GIRAFULL の 09-07 23:59 は、測定時刻（21:26）ではまだ過ぎていません。

ご指摘のとおり、暦日判定だと**締切を過ぎた回が最大24時間、受付中として画面に残ります**。利用者は応募できない抽選を見せられ、こちらは実際より多い社数を数えています。時刻が入っている行だけでも実時刻で判定すれば直せます（時刻が無い行は 23:59 とみなすのが自然です）。**直すかの判断をお願いします。**
