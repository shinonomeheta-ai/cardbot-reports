## 指示と実装の食い違い

1. **画面の商品タブは product_master を見ていない。** タブの振り分けは `page.js` の `setsForProduct(l.product, setNames)`（`lib/set-names.mjs`・名簿の弾名で部分一致）で、段2の影の欄は画面に配線していない（設計どおり。resolution の公開は #1337 で配るだけ）。したがって **set_only であることが理由で行がタブやカードから落ちることは無い**。

## 2. 影の欄が古い／無い行の原因と直し（PR #1348）

fill を「Fill receive method」の直後に置いていた。その後に行を作る・畳む段がある。

- update-data: `materialize_official_lotteries` が fill の**後**に行を作る → 影の欄なし（1-3 の 3 行）
- 両方: `collapse_open_duplicates` は「落とした行の欄のうち残す行に**無いものだけ**移す」ので、fill 後に作られた行（欄が無い）が、畳まれた短い商品名の行の影の欄（set_only）を受け取る → 長い名なのに set_only（1-1 の MINT GAMES・TierOne・TSUTAYA能代店）。次の巡回の fill は `r.get("product_master") != s` なら書き直すので、fill の位置が畳みより後なら消える

直し（PR #1348・head 35308b96）: 両 workflow で fill を `mark_similar_rounds` の直後（`Build shadow current events` の前）へ移す。この位置ではこの巡回で行を触る段は全部終わっている。段の数は変えない。`test_fill_product_master` に「materialize / promote / collapse / mark_similar / fill_receive より後」の順序の試験。手元 45 件 OK。

**CI（head 35308b96・run 34011423645）**: python test 7,503 件・失敗 3（`test_overrides_touch_identity` 1・`test_lottery_overrides` 2）。最新 main（7c4e30af）の clean checkout の赤（同じ3件＋`test_url_candidate`）の部分集合 → **PR 固有の赤 0**。この PR は workflow の段の移動と試験1本だけ。マージは判断待ち（指示があれば自分で `gh pr merge --merge`）。
