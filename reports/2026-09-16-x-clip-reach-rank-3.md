## 3. 「メルカリが出てこない」の正体（#1596）

**その話題は `news.json` に入っていた。**

```
2026-09-15  話題点 5.1  メルカリ出品禁止に対する転売ヤー・物販プレイヤーの反応
```

トピックに出ないのは、トピックが**反応ポストのある話題だけ**を候補にするため。そして反応は**1度も取りに行っていなかった**（`related_at` のキーごと無い）。**Xに反応が無いのではなく、うちが取りに行っていない。**

### 原因は金額ではなくリクエストの本数

`xai_budget.REQUEST_CAPS["P3"] = 2`。非中核の1日のリクエスト上限が2本で、1本はニュース探索が使う。**1リクエスト＝1話題**だったので、切り抜きに回るのは**1日1話題**だけだった。

`xai_call_log.jsonl` の実測:

```
ok       x_search   ← ニュース探索
ok       x_search   ← 切り抜き（1話題ぶん）
skipped  P3_daily_request_cap_reached
skipped  P3_daily_request_cap_reached
skipped  P3_daily_request_cap_reached
```

`related_at` の分布も **1日1件ずつ**で一致する。結果、反応待ちが **16件**たまり、メルカリはその4番目だった。

### 直したこと（上限は上げない）

```
いま:  1リクエスト → 1話題   → 1日1話題
直し:  1リクエスト → 4話題   → 1日4話題（本数は2本のまま）
```

`XAI_P3_DAILY_REQUESTS` は触っていない。増えるのは出力トークンだけで、非中核のUSD枠 **$0.28/日** に対し実消費は **$0.045/日**（`xai_call_log.jsonl` の中央値 $0.0225 × 2本）。予算ガードはそのまま効かせる。

### 壊さないための歯止め

* 1リクエストで挙げさせるURLの合計は **80件で頭打ち**。長すぎる返事は途中で切れて JSON ごと壊れ、**払ったぶんが丸ごと無駄になる**
* ただし1話題あたりは `NEWS_RELATED_MAX` を下回らせない（絞る前から足りないため）
* 返事は**話題の番号**で突き合わせる。渡していない番号は捨てる
* JSON が読めなかった回は、束の大きさと出力トークン数を添えて記録する

## 4. 前言の訂正

「行列が話題点順だから新しい話題が後回しになっている。順番を新しさ寄りに変えれば無料で直る」と一度書いたが、**これは誤り**。`score_of` は「話題の大きさ × 新しさ」で、新しさは既に掛かっている。古い6.6点が新しい5.1点より上なのは素の話題の大きさが違うため。ここに補正を足すと二重になるので、**順番は変えていない**。詰まりはリクエストの本数だけだった。
