# 1. KIDDY LAND の名前の繋ぎ — 3案

## いまの状態

```
M1g          canonical_name = "KIDDY LAND" ／ store_keys = ["KIDDY LAND"]
実際の店名     キデイランド原宿店・キデイランド大阪梅田店 …（カタカナ）

チェーン("キデイランド大阪梅田店")             = ""   ← 本部にも
チェーン("キデイランド大阪梅田店", 支店も=True)   = ""   ← **支店にも当たらない**
```

S6 が入れた24件は、このままでは **M1g の判定に1件も当たりません**（カードにも出ません）。

## 案あ — `extra_store_keys` に「キデイランド」を足す

* 効くのは**前方一致（支店判定）だけ**。「M1g の支店」として数えられるようになる
* **カードには出ません**（カードは完全一致だけを見る）
* しかも `extra_store_keys` は**実在する店名しか採らない**決まりで、
  「キデイランド」ちょうどの行が無いいまは**入りません**。規則の緩めが要ります
* → 数え方は直るが、ご指示の「カードに入れる」は達成できない

## 案い — 別名表（`store_aliases.json`）で寄せる

* 「キデイランド◯◯店 → KIDDY LAND」と書く
* **採れません。** 配る側（`build_lotteries_nyuka`）が**店名そのものを書き換える**ので、
  利用者の応募済み・既読の鍵（`lot_key`）が動きます
* → 実害があるので不可

## 案う（推奨）— 案1と一緒に直す

* 「**本部主体の企画は、支店の回もチェーンのカードへ寄せる**」を
  **チェーンごとに宣言する欄**を M1g に足す。たとえば

```
"branch_rounds_are_chainwide": true,
"branch_name_base": "キデイランド",
"branch_evidence": "LivePocket の各イベントに『キデイランドの複数店舗での重複応募は無効』
                    とあり、チェーン横断で応募を数えている（2026-09-07 実測）"
```

* カード側はそれを見て、支店の回を**商品ごとに畳んで**「受付中 n件」で出し、
  シートで**店舗と応募先の一覧**を出す（＝案1）
* **§3-1-1 を壊しません。** 宣言した店にだけ効き、宣言していない店は今までどおり
  「支店の回はカードに入れない」ままです

**案う でよければ、着手前に案1の設計案（欄の形・畳み方・シートの並び）を出します。**

# 3. X の登録 → PR #1379（**「27店」を訂正します**）

## 訂正

前便で「サイトが X を張っているのに登録が無い**27店**」と書きました。
**大半は、同じ口が別の登録名で既に登録済み**でした。

```
イトーヨーカドー   → @lets_go_yokado は「イトーヨーカドー各店」で登録済み
竜のしっぽ各店     → @shippo_online は「竜のしっぽ」で登録済み
ヤマシロヤ…      → @toy_yamashiroya は3つの名義で登録済み
イオン九州（アプリ） → @aeon_kyushu は既に2名義で登録済み        …ほか
```

`official_handle()` が**実際に引けなかった**のは **12件ほど**です。
27は「登録名が一致しない件数」で、「口が無い件数」ではありませんでした。
