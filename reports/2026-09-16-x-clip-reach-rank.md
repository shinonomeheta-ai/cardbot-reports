# トピックのX切り抜きを、反応の多い順に選んで並べる（PR #1593）

## 指示文（本人・2026-09-16）

> トピックにある記事のX切り抜きなんだけど、どれもインプレッションが低い。インプレッションが高いやつを優先して取るようにしてください。

追加指示（同日）:

> 並び替えは最大を一番上にして。インプレッション順に、15個以上切り抜いて。あとは順番をシャッフルしてください。

根拠データ: https://github.com/shinonomeheta-ai/cardbot-reports/blob/main/reports/data/2026-09-16-x-clip-reach.json

## 1. 何が起きていたか

トピックの記事に付くX切り抜きは `build_news.collect_related_posts`（Grok の `x_search`）が集めていて、**AIが返した順のまま保存**していた。その順は「話題との関連の強さ」であって、**読まれた量とは無関係**。

保存済みの切り抜きを全件計測した（2026-09-16・18話題143件）。

| 反応（いいね＋返信） | 件数 |
| --- | --- |
| 5未満 | 91件（64%） |
| 100以上 | 12件（8%） |
| 中央値 | 2 |
| 最大 / 最小 | 29,281 / 0 |

同じ話題の一覧に、いいね28,809の投稿といいね0の投稿が並んでいた。**上位と下位の差は4桁ある。**

## 2. 表示回数そのものは取れない（確認済み）

* 埋め込み用の `cdn.syndication.twimg.com/tweet-result`（すでに全社の公式X巡回で使っている口）が返すのは本文・画像・**いいね数・返信数**まで。`view_count` の欄は**計測した143件すべてで欠落**
* Grok の `x_search` にも下限を指定する引数は無い。あるのは `allowed_x_handles` / `excluded_x_handles` / `from_date` / `to_date` / `enable_image_understanding` / `enable_video_understanding` の6つだけ（docs.x.ai で確認）
* 表示回数はログインの要る公式API（有料・本数制限）でしか取れない

**そこで「いいね＋返信」を物差しにした。** 上位と下位の差が4桁あるので、順位付けの目的には足りる。この判断は `docs/assumptions.md` に記録した。

## 3. 直したもの

### `x_post_reach.py`（新規）

投稿の反応数を実測して選ぶ・並べる。

* `measure()` … 1件の反応数。取れなければ `reach=-1`（最後尾）で、例外は投げない
* `rank()` … 反応の多い順に選ぶ。足切りは反応5件、**15件までは足切り未満でも埋める**
* `arrange()` … **最大を先頭に固定し、2番目以降をシャッフル**

### `build_news.py`

* プロンプトに「いいね・リポスト・返信が多く、広く読まれている投稿を優先」を追加
* 聞く数を2倍（`NEWS_RELATED_ASK`・既定40）にして、**実数を測って絞る**
* `rerank_related_posts()` を追加。保存済みの切り抜きも測り直して並べ直す。反応数は後から伸びるので、**集めた直後の1回きりの並びを正としない**

### `rerank_news_posts.py`（新規）

既存データの作り直し用。無料（AIは呼ばない）。

## 4. 壊さないために置いた歯止め

1. **数が取れなかった投稿を「人気が無い」と読まない。** 保存済みを並べ直すときは最後尾に置くだけで捨てない。通信が一度こけただけで、払って集めたものを失わないため
2. **1件も測れなかった話題は触らない。** 通信が落ちている回に並べ直すと、全部が「反応0」に見えて順番が壊れる
3. **記事あたり2件は必ず残る。** `build_news.MIN_REACTIONS` を割ると `_stale_without_reactions` が記事ごと消す
4. **1話題につき1日1回まで**（`related_ranked_at`）。巡回は1日に何度も走るので、毎回並べ替えると反応数の小さな揺れで `news.json` が書き換わり、コミットと再デプロイだけが増える
5. **シャッフルの混ぜ方は顔ぶれで決まる**（種に残ったURLを使う）。同じ顔ぶれなら何度並べ直しても同じ順になる。4と同じ理由

## 5. 費用

**AIの呼び出し回数は増えない。** 増えるのは1話題あたりの出力トークンのみ（20件ぶん→40件ぶん・約1,400トークン）。並べ替えの計測はCDNへのGETだけで無料。

## 6. 効果（実データで確認）

`rerank_news_posts.py --dry` を実データ18話題143件に当てた結果:

```
先頭: 29,281 / 8,618 / 463 / 191 / 89 反応 …
落ちる切り抜き: 0件
```

**いまは1件も落ちない。** 15件以上残す指定にしたところ、どの話題も候補が7〜10件で15に届かないため。15件以上を実際に満たすには集める側の数が要るので、AIに聞く数を40件に上げてある（実際に返る数は話題しだい）。

`news.json` はPRに含めていない（データは巡回が持つ）。マージ後の `build_news.py` の実行で同じ並べ替えが自動で走る。
