# 抽選データの読み込みを軽くした（#1651・#1652）

2026-09-21。本人 2026-09-20「抽選データを開くときに重すぎるので、軽くなるようにしてください」。
PR #1651（`541ea0fa`）と #1652（`cf59a8a5`）をマージ。本番デプロイ成功。

## 測った（本番・直す前）

| | 値 |
| --- | --- |
| 一覧が出るまで | 4.7秒 |
| `/api/admin/candidate-review` | 16.5MB・5.6秒 |
| 札 | 5,315件（うち締切済み 3,346件） |

## 1手目 #1651: 締切済みを送らない

画面は前から締切済みを出していない（「締切済みの N件は出していません」）のに、サーバーは全部送っていた。
外向きの口は `scope=open` を既定にし、「出す」を押したときだけ `scope=all` で取り直す。

結果: **16.5MB → 6.0MB（-64%）**。ところが**時間は 5.4秒 → 5.0秒でほぼ変わらない**。

## 2手目 #1652: 同じコミットなら組み立て直さない

測り直すと、転送量に関係なく5秒だった（open 6MB も all 16.5MB も同じ）。
遅いのはサーバー側で、**毎回 GitHub から約50MB**を読んで札を組み立てていた。

    shadow_candidate_evidence_cache.json  31MB
    shadow_candidates.json                11MB
    shadow_candidate_ai.json             7.7MB  ほか10本

材料はコミットでしか変わらないので、main の先頭のコミット（1KB）だけを見て、同じなら前の答えを返す。
人が保存すると台帳へコミットするので、印は自動で変わる。

## 結果（本番で実測）

| | 直す前 | いま |
| --- | --- | --- |
| API（1回目・コミット直後） | 5.6秒 / 16.5MB | 5.8秒 / 6.0MB |
| API（2回目以降） | 5.0秒 | **0.7秒** |
| 一覧が出るまで（開き直し） | 4.7秒 | **0秒台**（開いた時点で出ている） |

## 残り

1回目とコミット直後は今までどおり約6秒かかる（50MBの読み込みそのものは減っていない）。
さらに詰めるなら、一覧に要らない欄（AIの詳細・抜粋・根拠の細目）を送らず、行を開いたときだけ取る段。
