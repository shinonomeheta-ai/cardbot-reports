## 1. 関門の枝

store-name-a の実装（形も場所も固定してもらっています）に、商品の段だけ枝を足します。

```
店:   台帳 → 無ければ ai値(res生, "store")
商品: 台帳 → 無ければ ai値(res生, "product")
             → 無ければ **M2（材料の本文）**            ← ここを足す
      そのうえで 扱う商品か()（M2 に寄るか）を通す
```

`扱う商品か()` の**手前**に置く理由は store-name-a の指摘どおりで、M2 で商品が決まっているなら寄せ直す必要がないためです。

### 入力は「その場で解決」（影の欄を読まない）

| | 影の欄を読む | **その場で `resolve_with_text`** |
|---|---|---|
| 正確さ | **1巡回古い**（`fill_product_master` は `promote` の後に走る） | いまの材料で決まる |
| 費用 | 0 | **0**（下記） |

```
M2 の読み込み             0.01 秒
resolve_with_text 1件     0.4 ms
根拠キャッシュの読み込み    0 秒 —— `promote` は既に読んでいる（`CA.round_fingerprint(cache, rid)`）
```

`AI昇格できるか` の呼び出し位置（`promote_candidate_decisions` 860 行）には `cache` が既にあるので、`cache[rid]["excerpt"]` を渡すだけです。判断⑪（入力は `resolve` の呼び出し）と同じ向きになります。

### 署名（store-name-a と相談中）

```python

```

引数追加が形を変えることに当たるなら、こちらで別関数に切り出します。

## 2. 行の商品名を M2 の `title` から

`昇格できる欄` の `product` は `ai値()` から採ります。**⑱ 由来の回は AI が商品名を返していない**ので、関門だけ開けると**商品名が空の行**ができます。

```
新規行を組む の product:
   ① 台帳の商品名                     （いまと同じ）
   ② 無ければ ai値(res, "product")     （いまと同じ）
   ③ 無ければ **M2 の title**          ← 足す（例: 「拡張パック「30th CELEBRATION」」）
```

**`event_id` は動きません。** 新規の行なので、`stable_event_id()` は誕生時にその行の store / product から決めます。既存の行の ID を書き換えるわけではありません（store-name-a の「AI の商品名で行を作れば正しい ID が最初から付く」と同じ形）。

M2 の `title` は公式一覧の表記そのままで、ゲーム名の前置きは付きません。表示側の前置きは画面の規則が足します。
