# Xの下書き: 管理画面で直して Discord へ出し直し、👍 でXへ・リンクから手で投稿も

## 指示

本人 2026-09-26:

> Discordに通知されてるやつが間違っていた場合に、管理画面で修正できるようにしたいんだけど、それって今ってなってるんだっけ？

> Discordに出した文章を管理して、下書きをさっと直せるようにしたい。それをDiscordに再通知して、それをいいねしたらXトライに飛ぶ。

（確認の質問「👍 を押したとき X への投稿はどうしたいか」に「両方」＝自動で投稿する／X の投稿画面を開く の両方）

## PR

https://github.com/shinonomeheta-ai/cardbot/pull/1677 （ブランチ `x-renotify`・7cc213eee）

### 流れ
1. Discord の下書きの「🛠 管理画面で直す」を押す → 管理画面のその下書きが開く
2. 本文を直して「直してDiscordへ出し直す」を押す（急ぐときは「今すぐ巡回を走らせる」）
3. 巡回が、同じ下書きを Discord に承認の下書き（👍📝🚫）として出し直す。古いメッセージには「出し直しました。こちらは押しても出ません」と返信
4. 新しい下書きに 👍 → 今までどおり巡回が X へ出す／「✍️ 手で投稿（出したら🚫）」→ 本文入りの X の投稿画面が開く（画像は手で付ける。手で出したら 🚫 を押す。押さないとあとの 👍 で二重に出る）

### 巡回（Python）
- `x_approval.renotify_pending`: 印（`renotify=want`）の付いた下書きを**同じ行のまま**出し直す。行の番号・型（朝夜・支店・ボックス別）・予約・画像・照合の行は引き継ぎ、Discord のメッセージ番号と合い言葉だけ付け替える。📝 の出し直し（`enqueue` で新しい行を作る）を使わないのは、型・予約・照合の行が新しい行に引き継がれないため
- 出し直さない: 出たか分からない下書き（`unknown_needs_reconcile`）、出す／取り下げの印がある下書き。`needs_fix` は `waiting` に戻す
- 順番は `enqueue` と同じ考え方（先に Discord へ出す → 行列を読み直して確かめて付け替える → 保存できなければ出した下書きを消す → 保存できてから古いほうへ返信）
- `approve_posts.py`: 時間帯の確認より前に呼ぶ（X へは出さないので時間帯の外でも）。落ちても投稿の処理は止めない
- Discord の下書きに合い言葉（16桁の16進）つきのリンク2行。本文はリンクに入れない（日本語が URL の中で約9倍に膨らみ、Discord の1通の上限に収まらない）

### 管理画面
- `/api/admin/x-intent?key=`: 本文入りで X の投稿画面を開く（管理者のみ・生きている下書きだけ。出し終えた下書きは開かない）
- `/api/admin/x-edit?key=`: 管理画面のその下書きを開く（まとめは「投稿を作る」、ほかは「Xの下書き」）
- `/api/admin/x-queue` の PUT に `renotify`。2画面に「直してDiscordへ出し直す」のボタンと状態（出し直し待ち／出し直し済み）
- 管理画面は URL から画面を選ばない決まり（nav-cleanup.test [13]）。例外として **Xの下書きの2画面だけ** URL から開けるようにし（`admin-deep-link.mjs`）、ログへは URL から入れないことを試験に足した
