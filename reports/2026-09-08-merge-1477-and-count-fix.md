# 2. 【訂正】数え方が違っていました。前方一致で支店を数えていました

も支店で拾っていました。

**「締切が未来の配信行 8」**（正しくは 93）という数を出しました。**帯の無い欄は JST と
みなす**、を入れて直しました。

# 3. 控えの赤を直す PR を出しました（#1478）

判断3の承認をいただいたので出しました。**課金には触れません。**

```
✓ 一次判定（Haiku）        batch 作成・成功（10〜11回）
X 控えがあることを確かめる    「控え 20 / 期待 10」で不一致
✓ Commit AI artifacts     batch は main に乗っている（回収できる）
```

二重チェック（`AI_DOUBLE_CHECK=1`）が入っていると、**1つの応募回が Batch へ `__a` と
`__b` の2リクエストを積みます**。控えは実際に POST した本数（20）を書き、意図台帳の
`requests` は応募回の数（10）を持つ——台帳が `requests == len(round_ids)` を自分で
強制しているので、**単位が違う**だけでした。

**直したのは期待値の側です。** 控えは「実際に払った本数」を書いたままにします
（払った記録を推定値へ寄せない）。**レーン数の判定は `candidate_ai_ab.lanes()` の
1か所だけ**に置き、送る側もそこへ委ねました——**同じ規則を2か所へ写すとずれる**ことが、
この件そのものだったためです。

**fail-closed は弱めていません。** レーン数を掛けるのは台帳の関門を全部通ったあとで、
OFF のときは今までと1バイトも変わりません。試験は新しく9件、既存の
`test_candidate_ai_haiku_first` ほか312件も OK。`docs/assumptions.md` に記録しました。
