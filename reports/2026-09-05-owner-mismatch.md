## 2. ハイパートレカ各店がCに入った理由（指示の確認）

**判定の穴でした。** 私のチェーン語の判定は**末尾**を見ています。

```python
チェーン語 = re.compile(r"(各店|各店舗|店舗|全店|通販|オンライン|オンラインショップ)$")
```

店名は `ハイパートレカ各店（駒井沢店・彦根店）` で、**「各店」のあとに括弧が続く**ため
末尾に当たりません。`〜各店` は当たりますが、`〜各店（…）` は当たらない。

同じ形は他にもあります（`BOOKSあんとく（みづま店・あらお店・やまが店）` など）。
**直す価値があります**が、A/C の分け方は「誰が担当するか」を決めるためのもので、
印そのものには影響しません（印はどちらにも付きます）。**この PR では触っていません。**

### 途中で1つ、関門を壊しかけました

最初の実装は台帳から `store_x_match` を import していました。
**その閉包は91モジュールあり、`resolve_urls` や `x_rewrite` へ届きます。**
`test_candidate_ai_haiku_first.test_5_通常実行経路からxAIへ届かない`
（候補AIの入口から xAI へ届かないことを守る試験）が落ちました。

```
xAI へ届く経路がある: ['notify_new_lotteries.py: api.x.ai', 'resolve_urls.py: XAI_API_KEY',
                       'store_name_ai.py: x.ai/v1', 'x_rewrite.py: api.x.ai', …]
```

**関門を迂回せず、依存の向きを変えました。** 公式X表を引数で受け、巡回の入口
（`build_candidates_shadow`）が `SX.official_accounts()` を渡します。
生の `store_x_accounts.json` は読みません——あちらは「読むところは全部ここを通す」と
決めた正本で、直に読むと誤登録がその経路だけ素通りします。

配線（入口が表を渡していること）と依存の向き（台帳が `store_x_match` を
import しないこと）の**両方を試験で守り**ました。
