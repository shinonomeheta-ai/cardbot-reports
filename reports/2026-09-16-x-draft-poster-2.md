## 本人からの指摘（作業のやり方）

> 毎回 CI 出さないでって言ったよね
> CIの経過を逐次じゃなくて、CI回さないでって。PythonテストとCI、重すぎるんだって毎回。

**1回目の指摘を「経過を報告するな」とだけ読み、回す回数そのものを減らさなかった。**
同じ日に push 4回（それぞれ python test 約15分＋web build check 約5分）に加え、
`gh workflow run` を main とブランチで2回起こしていた。

`.claude/CLAUDE.md` の「マージの条件」の下に決まりを書いた（`[skip ci]` 付きで push し、
新しい run が立たないことを確認済み）。

1. 手で workflow を起こさない（`gh workflow run` は使わない）
2. push は1回にまとめる（手元で試験・ビルドを全部通してから1回だけ）
3. 報告・ドキュメントだけの変更は `[skip ci]`
4. 確かめるのは手元。CI は**最後の1回**であって作業中の確認手段ではない

加えて、CI の経過（待ち・pending の一覧・run のURL）も本人へ出さない。
出すのは「PR 固有の赤（原因と直し方）」と「終わった（1行）」の2つだけ。
