## 1. 結論

**3つとも「規則が無い」のではなく「規則が呼ばれていない」穴だった。**

| | 穴 | 効き |
| --- | --- | --- |
| ① | X投稿の先を辿る控えが**1つの入口にしか渡っていなかった** | **299回**に応募URLが付く |
| ② | 「◯◯（各店）」の告知が1支店のものでも「各店」で出していた | 誤配0で**5頁**が支店名になる |
| ③ | 非抽選の判定が**AIへ送る待ち行列で見られていなかった** | 送る回 **−23**／母数 −107 |

どれも**判定そのものは既に在った**。呼び出しが繋がっていなかった。

---

## 2. ① 控えが1つの入口にしか渡っていなかった

`row_evidence(row, …, x_links)` に控えを渡していたのは、`lotteries.json` 由来の
行を組み立てる `build_candidates_shadow` **だけ**だった。

```
build_candidates_shadow.py       x_links を渡す      ← ここだけ辿っていた
merge_intake_artifacts.py        None                ← X取り込みの本体
backfill_candidate_master.py     省略
candidate_master_source_recovery 自前の写し
```

**X取り込みから生まれた候補は、投稿の先を1本も辿っていなかった。**
`hop()` は応募URLを返せるのに、呼ばれていなかった。

### 実測（`shadow_candidates.json` 2026-09-11 14:40 JST）

```
応募URLが無い理由 no_url_candidate   1,810回
  うち回の根拠にX投稿がある            1,696回
    ★ いまの控えだけで応募URLが出る      299回   ← これが付く
    短縮URLを展開できていない            573回   （投稿の entities が空・別件）
    投稿に外部リンクが無い               729回   （直せない）
    応募ページでないと判定                95回
```

### 直し

* `x_apply_links.控えから辿る()` を新設し、**控えの組み立てをここ1本**にした
  （同じものが3か所に写されていた・§11-1）
* `merge_intake_artifacts` / `backfill_candidate_master` /
  `candidate_master_source_recovery` を繋いだ。取り込みでは
  **いま入れた投稿をその場で材料へ足す**——次の行ではなくこの行が辿れないと、
  初めて見た告知の応募URLが次の巡回まで空になる
* **EC巡回と livepocket は繋がない。** `source_url` はECページと livepocket で
  X投稿が入らないので効果0、X台帳への依存だけ増える
* `url_quality.SHORTENERS` に**素の `r10.to`** を足した（`a.r10.to` だけ書いて
  あったので素のほうが関門を素通りし、`https://r10.to/…` のまま応募先になれた）。
  実測0件なので落ちる応募先は無い

**鍵は動かない。** `candidate_event_id` は URL を含まず（#1327）、`crnd_prov_` は
1件目の取得元だけを使う。応募先の根拠を足しても発番は変わらない。

## 3. ② 「ポケモンセンター（各店）」が支店1店の告知だった

`ec_lottery_sources.json` はポケモンセンターの店舗お知らせを**1つの店**として
登録している。`link` が**全支店のお知らせ頁に当たる**ので、支店1店の告知でも
店名が「ポケモンセンター（各店）」になっていた。

> 「台帳の店は『ポケモンセンター（各店）』だが本文はサッポロ支店のみ」
> （9/11 の有料AIの所見）

**やっていない店で「応募できる」と出していた。**

### 直し

`branch_from_notice.py` を新設（この判断だけを持つ・§11-1）。

```
① URL が支店の頁だと言っている   branch_url に当たる（登録した社だけ）
② 本文の冒頭が、名簿に在るその社の支店名を名乗っている
```

**2つが一致したときだけ**店名を変える。都道府県も名簿
（`store_official_map.json`・公式の店舗地図 2,616店）から入れる——束ね名では
2県以上に当たって空で、地域の絞り込みに乗っていなかった（#1508 と同じ趣旨）。

### ★ 途中で2回外した（どちらも実測で見つけた）

1. **切り詰めた偽の店名を作った。** 最初は「本文の冒頭から社名に続く文字を取る」
   形にしたら `ポケモンセンタースカイツリータウ` ができた。弾名の切り詰めと
   同じ型で、出すと**存在しない店が1つ増える**。
   → **名簿に在る名前だけ**返す形に変えた。名前をこちらで組み立てない
2. **見る範囲を広げて壊した。** 本文の先頭を400字にしたら、頁の下の支店一覧まで
   入り、**ヒロシマの頁もカナザワの頁も「スカイツリータウン」**になった。
   → 先頭60字＋**先に名乗ったほう**を採る（同じ位置なら長いほう）。回帰試験つき

### 実測（保存済みの頁本文・通信0）

```
shop.pokemon.co.jp の頁         20件
  common（全店）の頁              3件 → **1件も支店にしない**（誤配 0）
  支店URLの頁                    17件 → 名簿と一致して名乗れた 5件
                                       本文がJSだけで名乗れない 12件
```

名乗れた5件は**URLのスラッグ・名簿・都道府県が全件一致**した。

```
hiroshima   → ポケモンセンターヒロシマ（広島県）
kanazawa    → ポケモンセンターカナザワ（石川県）
skytreetown → ポケモンセンタースカイツリータウン（東京都）
tokyobay    → ポケモンカードステーション・ポケモンセンタートウキョーベイ（千葉県）
tokyodx     → ポケモンセンタートウキョーDX（東京都）
```

名乗れない12件は**そのまままとめ名で出る**（いまと同じ）。

## 4. ③ 非抽選の判定が、待ち行列で見られていなかった

非抽選の判定（`not_a_lottery`）は**取り込みの入口にしか無く**、AIへ送る待ち行列
では見ていなかった。だから既に「抽選の語なし」と判定済みの回まで有料で送って
いた（9/11 の39件のうち2件が実際にそれ）。

### 実測（送れる回 774件を通した）

```
抽選として通る   693
抽選の語なし      58   ← **門にしない**
抽選ではない      11
結果               8
懸賞               2
対象外             1
店頭くじ           1
```

### 直し

* `check_candidates_ai.非抽選の理由()` を新設。門は `R.対象()` の**1か所**
  ——有料のレーンは Haiku と Sonnet の2本あり、レーンごとに書くと増えたときに
  素通りする。Sonnet の `rejudge_before` の枝は `R.対象` を通らないので、
  そこにも同じ判定を置いた
* `非抽選も=True` で全件監査のときだけ通す
* **落とした数と理由を残す**（`excluded_non_lottery` /
  `excluded_non_lottery_reasons`）。黙って減らさない（§10）

### ★ `抽選の語なし` を門にしてはいけない

あれは「抜粋に抽選の語が無い」で、**抜粋が壊れている回も同じ札**になる。
ポケモンセンターの店舗お知らせは本文が `window.dataLayer …` だけで取れており、
実物は抽選の告知。**落とすと本物を失う。** 直す相手は抜粋のほう。回帰試験つき。

### 景品の語を6つ足した（本文を1件ずつ読んでから）

```
ヤマダデンキ   SALONIA のヘアアイロン／山善 防災バッグ
楽天ブックス   お買いものパンダデザインの図書カードNEXT
セブンネット   映画のポスター(B2)
GEO           直筆サイン入色紙（本文に #懸賞 と書いてある）
ビックカメラ   横浜FC 公式戦へご招待
```

**抜粋を持つ 3,540回へ当てて、当たったのは6件。すべて狙ったもの。誤爆0。**

### ★ ガンギは入れなかった（私の読み違いを実測で直した）

前版で「トレカでない企画」に**ガンギ（ガンプラ）**を挙げたが、この回の本文は

> 【ポケカ抽選販売のお知らせ】ポケモンカードゲーム「スペシャルデッキセットex
> フシギバナ・リザードン・カメックス」が入荷しました

で、**本物のトレカ**だった。別の回と混同していた。
**景品の語を足す前に本文を読む。**

## 5. 構造の見張りに止められたので、緩めずに直した

③の門を `check_candidates_ai` に置いたら、全試験で1件増えた。

```
test_candidate_ai_haiku_first.test_5_通常実行経路からxAIへ届かない
xAI へ届く経路がある: ['build_lotteries.py: api.x.ai', …15件]
```

`official_x_intake` は取り込みの重い相手（`candidate_ledger` など）を通じて
**xAI を叩くモジュールまで import で辿れる**。有料Haikuの経路が xAI へ届いては
いけないという見張りである。

**見張りは緩めず、構造を直した。** `lottery_notice_words.py`（`re` しか読み込ま
ない葉）へ語彙と判定を**行番号で機械的に**移し、`official_x_intake` は呼ぶだけに
した（名前は再公開するので呼び出し側と試験は動かない）。判定は1か所のまま。

これで赤は7件に戻った。

## 8. 今日の教訓

1. **規則はあったが、呼ばれていなかった。** 3つとも新しい判定は要らず、
   繋ぎ直しだけで効いた。**「無い」と決める前に、呼ばれているかを見る**
2. **見る範囲を広げると壊れる。** 本文60字→400字で、どの支店の頁も同じ名前に
   なった。広げる変更は**広げる前後で測る**
3. **名前は作らない。名簿と突き合わせる。** 組み立てると切り詰めた偽名ができる
4. **関門は強さの順で間違う。** `抽選の語なし` は落としたくなる札だが、
   抜粋の壊れと見分けられない。**落とす前に、落とす物を読む**
5. **景品の語を足す前に本文を読む。** ガンギを「ガンプラ」と読み違えていた
