# 配色の既定を端末の設定に戻す（PR #1614）

本人指示 2026-09-18「画面のUI、ダークモードとライトモードをユーザーの設定に
してね。嫌いな人もいるかもしれないから。今ダークモード固定になってるでしょ」。

**2026-09-15 の「ダークを既定にする」を取り消す。**

## いまの作り

配色の仕組みは前からあり、選び方は7つ（自動／ホワイト／ボルト／ボルト夜／
スチール／クリーム／ダーク）。**壊れていたのは既定だけ。**

2026-09-15 に「明るい端末でも最初からダークで出したい」という指定で、
`auto` を既定から外し、**保存の無い端末と「自動のまま」の端末を一度だけ
`dark` へ寄せる**移行を入れていた。これで新規の人は全員ダークになる。

## 入れたもの

* 既定を `auto`（端末の `prefers-color-scheme`）へ戻す。明るい端末なら
  ボルト、暗い端末ならダーク。**時刻では切り替えない**
* 09-15 の移行が黙って `dark` を書いた端末を、一度だけ自動へ戻す
* これ以降、人が配色を選んだら**手で選んだ印**（`cardbot-theme-picked`）を
  残す。既定を動かす移行が、その人の選択を上書きしないようにする

画面から変えるところは右上の明暗ボタン（☀／🌙）。**押して戻すと自動に
帰る**作りは前からある（行き先が端末の設定と同じなら `auto` を保存する）。

## 採った仮定

前の移行は `!saved || saved === "auto"` で `dark` を書いたので、
「自分でダークを選んだ端末」と**区別が付かない**。印を付ける仕組みは今回
入れたもので、それ以前に手でダークを選んだ端末には印が無い。

そこは**一度だけ自動へ戻る**ことを受け入れた。暗い端末なら見た目は変わらず、
明るい端末でもボタン1つで戻せる。押し付けを消すほうを採った。

## 試験

`theme-default.test.mjs` は**文字合わせではなく台本を実際に走らせる**
（`node:vm` に localStorage と matchMedia の偽物を渡す）。既定の移行は保存を
書き換えるので、条件を間違えると「自分で選んだ配色が黙って変わる」という
一番まずい事故になる。

| 端末 | 期待 | 結果 |
| --- | --- | --- |
| 新品・明るい | auto → ボルト | OK |
| 新品・暗い | auto → ダーク | OK |
| 前の移行で dark を書かれた（印なし）・明るい | auto → ボルト | OK |
| 手で選んだ5配色（印あり） | そのまま | OK |
| 2度目の起動 | 動かさない | OK |
| `?theme=steel` の見比べ | 保存を汚さない | OK |

* 新規6件 OK ／ `manifest.test.mjs` の「既定はダーク」を入れ替えて11件 OK
* `cd web && node --test app` → 落ちた41件は枝分かれ元と完全一致（差分0）
* `npx next build` 成功

## 途中で踏んだもの

台本は**テンプレートリテラルの中**にあるので、注釈に素のバッククォートを
書くとそこで文字列が閉じてビルドが落ちる。`\`applyTheme()\`` と逃がす。
#1601 の「`<style>` に `>` を直接書かない」と同じ形。

## 残す形

PWA の起動の幕（manifest の `background_color`）は暗いまま。
`link[rel=manifest]` の media はどのブラウザも見ないので明暗で出し分け
られない（w3c/manifest#955）。明るい端末では最初の1〜2秒だけ暗い。

`ThemeToggle`（7つから選ぶ一覧）は**どこからも使われていない**。
いま画面にあるのは右上の明暗ボタンだけ。今回は触っていない。
