## 【本題】25件に効く一般的な問題を見つけました

バンビの印が付いた理由は、別名でも正式名でもなく、**2つの正規化が `【】` で
食い違っていること**でした。

```
'CARDBOX おもちゃのバンビ本郷店'
   EI.norm    = 'cardboxおもちゃのバンビ本郷店'
   tenant_key = 'cardboxおもちゃのバンビ本郷店'
'【CARDBOX】おもちゃのバンビ 本郷店'
   EI.norm    = 'cardboxおもちゃのバンビ本郷店'     ← 同じ（台帳では1行）
   tenant_key = '【cardbox】おもちゃのバンビ本郷店'  ← 違う（権限では別の鍵）
```

```
event_identity.norm   [\s　「」『』【】()（）・･_/\\-]+ を落とす
date_source.tenant_key [\s\-‐–—_/／・･,、。．.]+ を落とす      ← 括弧を落とさない
```

**台帳では同じ店なのに、公式Xの引きでは別の鍵**になります。
`【】` を含む表の鍵は **25件**あるので、その全部でこの食い違いが起きます。


**+1 / -0。** いま効くのは1件ですが、25件ぶんの食い違いの種が消えます。

`tenant_key` は権限の鍵なので、**変えるかどうかは判断が要ります**。
段2 で `_norm` を外したときと同じ性質の変更です（語は落とさないまま、
括弧だけを落とす）。実装していません。
