# CI が教えてくれたこと

マージの前に CI を突き合わせたところ、**main には無い赤が1件**出ていました。

```
test_own_source_apply_url.test_元のurl_rawと新しい候補が両方残る
   期待   https://shop.joshin.co.jp/lottery/1
   実際   ''
```

手元で追ったところ、**この PR が原因**でした。

```
登録前   shop.joshin.co.jp は**どの店のものでもない**
        → 店「Joshin」の行が、この応募先を own source として採れていた

登録後   ホストが**別の登録名**（ジョーシン（アプリ））のものになる
        → 「Joshin」から見ると**よその店のホスト**になり、採らなくなった
```

## 分かったこと

> **ホストを2つ目の名前で登録すると、1つ目から取り上げてしまいます。**

`store_sites.json` は**1名義1URL**なので、同じホストを両方の名義へ持たせられません。
「登録すれば増えるだけ」ではなく、**別の名義の判定を減らすことがある**、という形です。

`host_belongs_to = True` になったのは事実ですが、**それは「ジョーシン（アプリ）」から見た話**で、
`Joshin` から見ると False へ変わっていました。**私の前便の見立ては、片側しか見ていませんでした。**

---

# 直したこと

```
ジョーシン（アプリ）  → **登録しない**（外した）
トレカショップ スキップ → 登録（skip-tcg.com）
レプトン各店        → 登録（lepton.ne.jp）

store_sites の登録   157（158 ではありません）
S1 の対象           141 → 155（#1385 の14件）→ **157**
```

試験は155件 OK（`test_own_source_apply_url` / `test_url_candidate` /
`test_shadow_url_owner` / `test_golden_chains_data` / `test_line_endings`）。

**スキップとレプトンは同じ問題を起こしません**（どちらのホストも他の名義が持っていない）。

# ジョーシンをどうするか（判断をお願いします）

* **案1**: `Joshin`（M1g のチェーン名）の名義で `shop.joshin.co.jp` を登録する。
  ただし `Joshin` には既に `joshinweb.jp` が登録してあり、**1名義1URLなので置き換えになります**
  （`joshinweb.jp` を失う）
* **案2**: `store_sites.json` を**1名義に複数URL**（配列）へ広げる。
  `url_quality.store_hosts()` は既に配列を受け取れますが、**他の読み手**
  （`date_source` / `official_page_intake` / `store_ledger` ほか十数か所）が
  文字列を前提にしているので、**そちらの点検が要ります**
* **案3（いま）**: 登録しない。`shop.joshin.co.jp` は誰のものでもないまま、
  `Joshin` が own source として採れる状態を保つ

**私は案3のままを勧めます。** いま困っていないのに、十数か所を触る理由が弱いためです。
案2は「1店が複数のドメインを持つ」ことが増えてから、まとめてやるほうが安全です。
