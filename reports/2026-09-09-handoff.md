## 3. 次にやること（順番つき）

### ① CI の型分けを続ける（いまここ）

**残る赤5件**（ASCII で数えた内訳）:

```
test_dedupe_channel            1  ← 実データ（どのクラスか未確認）
test_shadow_url_owner          1  ← B
test_url_fields                1  ← B
test_shared_platform_gate      1  ← B
test_candidate_ai_haiku_first  1  ← C（月次予算 $100.15 > $100）
```

**この3件（shadow_url_owner / url_fields / shared_platform_gate）は今日ずっと
出たり消えたりしている。** 巡回がデータを書き換えるたびに変わる。
**B型が python-test に残る限り、赤の数は安定しない。**

やり方は #1495 と同じ。

```
1. 1件ずつ実際に走らせて型を確かめる（名前では区別できない）
2. B なら data_check.実データの検査 の印を付ける
3. **契約の一覧へは入れない。** 移行中の実データ検査 へ書く
   （実データに対して赤なので、契約＝push を止める関門に入れると巡回が止まる）
4. 中身を直して緑になってから、契約の一覧へ移す
```

`test_data_contract.移行中の実データ検査` は**空にするのが目標**。
いま4件入っている。

### ② 移行中の4件の中身を直す

```
test_candidate_ai_runner.抜粋の版Tests / 支店の境界Tests
test_lottery_overrides.管理用の控えTests
test_event_id_redirects.リダイレクト台帳Tests
```

**4件目の原因は分かっている。** `EI.event_id_redirects(path)` は
**人の台帳（`path` で差し替えられる）と機械の台帳（`auto_redirects_path()`・
差し替えられない）を合わせて返す**。試験は人の台帳だけ差し替えて「1件だけ返る」と
期待しているので、機械の台帳に行が増えた日から落ちる。
**バグではなく、試験の期待が仕様と食い違っている。**

### ③ C型の1件

```
test_candidate_ai_haiku_first.課金前の決着
  今月の引当 $100.15（$99.11 ＋ 試験の $1.05）> 天井 $100.00
```

**実際の月次予算の残高を読んでいる。** 材料を隔離する（#1493 と同じ考え方）。

### ④ 第2段の残り（DB）

| | |
| --- | --- |
| A | 突き合わせの判定を**取得時刻**で見る。いまは前方一致だけで粗く、「移行後に更新された」と「本当に食い違っている」を分けられない |
| B | **3モジュールの差し替え**。`linked_page_cache` / `candidate_ai_cache` / `official_x_ledger` の中身を `source_store` へ向ける。**呼ぶ側は1行も変えない**のが目標 |
| C | `x_post` のデータ移行 |

**B の手順は固定。間に巡回を挟まない。**

```
移行を流し直す（冪等・4分）
 → compare_source_store で「消える・減る」が 0 を確認
 → その足で切り替える
```

**2026-09-08 16:24 の実測で 311件**だった（移行の2時間後）。
`source` は移行時点の断面で止まるので、**時間が経つほどずれる**。

## 4. 触ると危ないところ

* **`lottery_io.save()`** — 配るデータを書くいちばんきわどい場所。
  `round_id` は `守る()` で発番され `_古い応募回を外す()` で外れる。
  **出入りするので、書き出す直前が唯一の確定点。**
  手元では巡回の挙動を再現できない（`本番` の判定が path で変わる）ので、
  **推測で行を消す処理を入れない。計測器を先に入れる**（#1490 → #1491 の形）
* **データ契約**（`test_data_contract`）— 落ちたら push を止める。
  **赤いものをここへ入れると巡回が止まる**
* **`test_data_contract.load_tests`** — クラスを作っただけでは関門は素通りする。
  **配線を忘れると「緑のまま何も見ていない」になる**（今日3回踏んだ型）

## 7. 前任が今日踏んだ誤り（同じ形を繰り返さないために）

| 誤り | どう分かったか |
| --- | --- |
| 直す場所を推測で**2回**外した | 計測器を入れて巡回1回で決着 |
| **古い基準で CI を4回比べた** | 基準は20分で腐る。数だけ見る／型分けで根を断つ |
| 「`round_id` 非空を関門に」 | **空は正当**（`_古い応募回を外す()` が意図的に外す） |
| 「本文の直読み4本」 | **実際は2本**、どちらも workflow から走らない使い捨て |
| 「`url` を主キーに」 | **92組**が正規化すると同じページ。移行前に気づいた |
| 「本当のバグ3件」 | **全部違った**（2件は時間で腐る試験・1件は月次予算） |
| **「赤9件」「9→6」** | **化けた名前を数えていた。正しくは 8→5** |
| 印を付けるスクリプトの判定が甘く1件飛ばした | 付けたあとに走らせて気づいた |
| heredoc の罠を**2回** | `\` が潰れる。Write でファイルに書いてから実行 |
| 根拠なく巡回の切れ目を**2回**待った | 触るファイルが巡回の書くものと重ならなければ、またいでよい |

**共通する型: 実物を走らせる前に、名前や見た目で判断して言った。**

**効いた判断はどれも「先に測る道具を作った」もの。**

```
計測器（#1490）          推測2回で外した場所を、巡回1回で特定した
突き合わせ（#1492）      切替前に 311件の事故を止めた
立て忘れの見張り（#1494） 「緑のまま何も見ていない」を防ぐ
```
