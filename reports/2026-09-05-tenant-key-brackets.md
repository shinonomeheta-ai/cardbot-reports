## 4. 設計書 §11-1-1（ご依頼）

```
event_identity.norm     [\s　「」『』【】()（）・･_/\-]+   括弧を落とす
date_source.tenant_key  [\s\-‐–—_/／・･,、。．.]+          落としていなかった
store_x_match._norm     同上 ＋ 語（通販・各店・公式…）を落とす
```

**規則が1か所でも、材料（正規化）が複数あれば分散は続く。**
正規化を新しく足すとき、既存のどれと同じ並びにするかを必ず書くこと、
JS 側にも同じ並びが要ること、を書きました。

## 5. 試験

```
python -m unittest discover   Ran 7,326   失敗は main と同じもの＋環境由来のみ
node --test app               3,605 pass / 0 fail
```

足した試験:

```
Python  括弧は落とす（【CARDBOX】… で引ける）
        括弧を落としても語は落とさない（ドラゴンスター / ドラゴンスター通販）
JS      tenantKey は括弧も落とす
        tenantKey は語は落とさない（[P1] の線）
        normStoreName は括弧を落とさない（写しのまま）
```

**直した試験**: `test_register_x_from_evidence` の
「綴りが違っても登録済みなら対象にしない」は、材料が
`CARDBOX おもちゃのバンビ本郷店` ↔ `【CARDBOX】…` でした。
**括弧を鍵が吸収するようになったので前提が消えました。**
鍵では吸収しない違い（語そのもの）の例へ移し
（`福福秋葉原店` ↔ `福福トレカ秋葉原店`）、括弧が吸収されることを確かめる
試験も足しています。
