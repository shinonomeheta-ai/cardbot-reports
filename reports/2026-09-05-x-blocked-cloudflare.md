## 3. 描画で runner が受け取っているもの（ご質問3）── 決定的

Chrome で描画したあとの中身:


**Cloudflare のボット検査ページ**です。ログイン要求でも空ページでもありません。

### なぜログに何も出なかったか

`render_text` は Chrome を起動して DOM を取るところまで**成功します**。返ってきた
HTML に `/status/` のリンクが1本も無いだけなので、例外は出ません。呼び元は
「0件取れた」として静かに次の店へ進みます。

そのため**ログには 429 の行しか残らず、描画が全滅していることが見えませんでした**。
1店あたり2.2秒（429が0.2秒＋検査ページの描画が2秒）で、正常時の13〜14秒とは
明らかに違っていたのに、そこも計っていませんでした。

## 5. 【否定】ヘッダ・User-Agent の見直しは効きません

手元で、同じ瞬間・同じURL・同じUAで比べました。

| 出し方 | 結果 |
| --- | --- |
| Python urllib ＋ いまのUA | 429 |
| Python urllib ＋ 整えたUA（`(KHTML, like Gecko)` 入り） | 429 |
| Python urllib ＋ 整えたUA＋Accept系ヘッダ | 429 |
| curl ＋ いまのUA ＋ HTTP/1.1 | **200** |
| curl ＋ 整えたUA ＋ HTTP/2 | **200** |

UAもHTTPの版も揃えて、curl だけ通ります。**見分けているのはUAではなく、
TLSの握手の指紋（クライアントの癖）です。**

ただしこれは**手元の話**で、**runner では curl でも 429** です。runner 側は
IP帯で先に落とされているので、クライアントを替えても手当てになりません。
