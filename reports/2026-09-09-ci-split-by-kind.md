## 1. 入れたもの（#1494・マージ済み）

CI の赤には性質の違う3つが混ざっている。

```
A 規則の検査          外を読まない            決定的
B いまのデータの状態  lotteries.json など     巡回が20〜30分ごとに書き換える
C 外の状態で腐る      現在時刻・月次予算残高   #1493 で2件直した
```

B を `python-test.yml`（`unittest discover`）に置いていると、**コードを1行も
触っていない PR が巡回のせいで赤くなる**。基準を取っても20分で古くなり、
「PR の赤を main の基準と差分で見る」が成り立たない（2026-09-08 に4回踏んだ）。

### 仕組み

| | |
| --- | --- |
| `data_check.py` | 印は1か所（`実データの検査`）。各試験に条件を書き写さない |
| data-contract | `export CARDBOT_DATA_CHECK=1`（ここでだけ走る） |

```
python-test.yml   飛ばす。**PR の赤は必ずコードのせい**になる
データ契約         走る。押す直前・その回のデータ・落ちたら push を止める
```

### この判断は 2026-08-10 に一度されている

`test_lot_key.py` にそのまま書いてある——「**生データへの assert をやめた**。
巡回がデータを書き換えるたびに、コードを1行も触っていない PR が落ちる。規則
そのものは固定の材料で見る。**いまのデータがどうかは `check_health` が見る**」。

**正しい形は決まっていて、そのあと同じ型が増え続けた。**

### 立て忘れの見張りを同じコミットに

飛ばすようにしたぶん、**契約側で環境変数を立て忘れると実データの検査が丸ごと
黙って飛ぶ**。落ちるのではなく「**緑のまま何も見ていない**」になる。

今日いちばん多く踏んだ壊れ方がこれだった（`test_data_contract.load_tests` への
配線を忘れて関門が素通りしていた・#1486 の作業中）。

`test_data_contract.実データの検査がここで走る` で字面を見張る。

* data-contract が `export CARDBOT_DATA_CHECK=1` を持っている
* 印は `data_check` の1か所にある
* **印を付けた試験は契約の一覧に入っている**（片方だけやると検査が消える）

### 試験台は1件だけ

**一気に移さない。** 1つ移すごとに巡回1回で確かめる（一気にやると、どれが
原因か分からなくなる）。今回は `test_dedupe_channel.実データ` の1件で、
**あれは既に契約の一覧に入っていた**ので、両方で走っていたぶんを片方にした。

**赤は減っていない。** あの試験は今日入れた畳み（#1485・#1491）で重複が消え、
**既に緑になっていた**。仕組みが入っただけ、が正しい報告。
