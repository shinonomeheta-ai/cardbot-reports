#### なぜ「古い」と言えるか

`lottery-admin.json` と `lotteries.json` は**同じコミットで更新されている**
（`a24c1837` ほか直近5コミットすべて）。つまりコミットをまたぐ遅れではない。

そのうえで、**いまの `event_id_registry.json` は 308 行すべてに `event_id` を
当てられる**（`attach_event_ids` で解決できない行は 0）。

```
刻んだ 308 / いまの registry で event_id が付かない 0 / 付くのに控えに無い 7
```

控えの書き手はこうなっている（`lottery_overrides.管理用の控え`）。

```python
rid = _trim(r.get(ROUND_ON_ROW)); eid = _trim(r.get("event_id"))
if not (rid and eid):
    continue          # ← event_id が無い行は入れない
```

そして `event_id` は `current_records.attach_event_ids` が
**registry に居るときだけ**付ける（新しい回には付かない。`stable_event_id` へ
落ちる道はここには無い）。

したがって順番はこうなる。

```
巡回 → 新しい回に round_id が刻まれる（応募回台帳は追記）
     → その時点で registry にはまだ居ない → event_id が付かない
     → 控えの書き手が「eid が無い」ので飛ばす      ← ここで 7 行が落ちる
     → 後段で registry が作り直され、その回も引けるようになる
     → 同じコミットに両方が入る（＝控えだけ1周ぶん古い）
```

**守り（`eid` が無い行は入れない）は設計どおり**で、破れてはいない。
落ちているのは「控えが registry より先に書かれる」という run の中の順番。
次の巡回で解消する種類の赤で、実際 7 行はすべて 9/5〜9/13 の新しい回である。

#### 案E（URLを素性から外す）との関係 — **ここが要注意**

控えの鍵は **`event_id#round_id`** である。案Eは `event_id` の導出を変えるので、
**控えの 305 本の鍵がすべて別物になる**。

- `test_成果物の行と控えの鍵がつながっている` は 7 → **約 308 本の欠け**になる

  **旧鍵のまま孤立する**

**移行では `lottery-admin.json` と `lottery_overrides` の entries も
同じ PR で鍵を貼り替える必要がある。** 鍵1,901本の追記が registry だけを
対象にしているなら、この2つが取り残される。

## c. `list-page-not-by-name` をどこにどう記録したか

置き場はこれ。

```
C:\Users\koya_Admin\.claude\projects\D--cardbot\memory\list-page-not-by-name.md
  ＋ 同ディレクトリの MEMORY.md に1行の索引
```

**セッションはまたぐが、人とリポジトリはまたがない。** このディレクトリは
プロジェクト単位で、次のセッションの開始時に索引が読み込まれる。ただし
**リポジトリの外**にあるので、レビュー担当も他のツールも読めず、版管理もされない。

指示の「残らないなら docs に渡すこと」に沿って、**docs へ渡す文面をここに置く**。
`docs/` は docs セッションの持ち場なので、私からは編集していない。

> **告知一覧の場所を名前で決めない**（2026-09-07・S2b）
>
> `news` `blog` `information` という名前は、その店がそこに何を置いているかを
> 表さない。晴れる屋2 の `/blogs/news` は読み物で、20記事とも抽選ではなかった
> （抽選の告知は `/pages/` の特設ページ）。名前で決めると「読めている・記事も
> 取れている・抽選だけ0」という顔になり、動いていないことに気づけない。
>
> 一覧を登録する前に、**その一覧から取れた記事を判定へ通して「抽選と判定された数」
> を見る**。0 なら場所が違う。site 検索を一覧の代わりにする道（`search` 欄）が
> 既にあるので、新しく作らずそれを使う。
>
> **0件のときは「場所が違う」と「拾えていない」の両方を疑う。** 同じ日に、
> `href` 末尾の空白で記事を全部捨てていた不具合（`記事リンク`）も見つかっている。
