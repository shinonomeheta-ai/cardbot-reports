### 1-1. rebase の修正

`official-x-web-discovery.yml` の型を**そのまま**持ってきました。新しい方式は作っていません。

```
成果物を退避 → git fetch → git reset --hard origin/main → 意味で再適用 → push（5回まで）
```

「意味で再適用」の中身は、**この回に入れたぶんを巡回本体と同じ入り口へ通し直すだけ**です。

- 巡回が `official_x_intake_delta.json` に「何を入れたか」（handle・店名・投稿ID・本文・
  リンク・画像・見た投稿ID・cursor）を残す。台帳ではないので**コミットしません**（`.gitignore` 済み）
- `merge_intake_artifacts.py` が最新mainの台帳を読み、その控えを `OXL.upsert` /
  `CL.upsert` へ通し直す

台帳は両方とも「足すだけ・何も消さない」upsert なので、並行して入った他の変更
（人の判定・AIの結果）を踏み潰しません。**独自のマージ規則は1行も書いていません**
——そこが新しいバグの置き場になるからです。

**再適用が失敗したら押さずに落とします**（`::error::` + `exit 1`）。空のまま
「変化なし」で緑に終わると、直そうとしている握り潰しと同じことになります。

## 4. 費用の見積りを訂正します

### 実測

| | 修正前 | 修正後 |
| --- | ---: | ---: |
| 1アカウントあたり | 10.7秒（うち sleep 6秒） | **7.0秒** |
| アカウント間の間隔（中央値） | 11.9秒 | **6.8秒** |

**削減は 3.7秒/件**で、見積りの 6.0秒より小さいです。前回は「10.7 − 6 = 正味 4.7秒」と
引き算しましたが、正味の時間は**その回の syndication 失敗率で変わります**。今回は
100%失敗＝全部が遅い描画経路という最悪条件でした。

### 依頼3（1日1周）の計算し直し

7.0秒/件（最悪条件）で 1,318アカウントを1日1周すると:

| 回数/日 | 1回の件数 | 1回の所要 | 分/日 | 分/月 | 追加費用/月 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 2 | 659 | 79分（timeout 100分要） | 158 | 4,750 | **$22.0** |
| 3 | 440 | 54分（timeout 70分要） | 161 | 4,840 | **$22.7** |
| 4 | 330 | 41分（timeout 53分要） | 164 | 4,930 | **$23.4** |

**前回の $10.5/月 は $21〜23/月 に訂正**します（月予算 ¥5,000 ≒ $33 の内側ではあります）。
syndication が通る回が混ざれば下がるので、これは上限側の数字です。

また **timeout を47分へ、では足りません**。3回×440件なら **70分**が要ります
（現在は40分）。

依頼3〜5は「1 の効果を実測してから判断」とのことなので、ここまでの実測をお渡しして
