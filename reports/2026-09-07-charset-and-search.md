## 1. 文字コード（PR #1437）

新しく `html_charset.py`。判定はここ1本です。

```
1. BOM（utf-8-sig / utf-16）
2. HTTPヘッダーの charset
3. HTML先頭8KBの <meta charset> / <meta http-equiv>
4. 宣言が無ければ UTF-8 → cp932 → euc_jp の順に試す
5. どれも駄目なら UTF-8 の replace（今までと同じ・落とさない）
```

**宣言があっても、それで壊れるなら次を試します。** utf-8 と名乗る cp932 のページが実在するためです。

寄せた口は4つ。

| ファイル | 直した箇所 |
| --- | --- |
| `linked_page_cache.py` | 一件を取る（応募ページ・告知ページの本文） |
| `url_quality.py` | t.co の meta refresh・本文の取得・描画の出力（3か所） |
| `ec_lottery_watch.py` | 一覧を開く |
| `candidate_evidence_fetch.py` | 自前の `_文字コード` を捨てて `html_charset` を指す |

JSON（APIの応答）の `decode("utf-8")` は対象外です（UTF-8 で正しい）。

### ただし search は効いていません

イエローサブマリンと iAEON に足して実測しました。

| 社 | search 無し | search 有り |
| --- | --- | --- |
| イエローサブマリン | 6件 | **6件**（増えない） |
| イオン九州（iAEON） | 1件 | **1件**（増えない） |

理由は検索そのものです。`検索で一覧()` は Yahoo 検索（`site:host 抽選 カードゲーム`）を叩きますが、**戻ってくるのは 4KB ほどで、中身は検索ページのナビゲーションのリンク**です。

```
yellowsubmarine.co.jp: 戻り 4,217字 リンク33本 → 先頭は search.yahoo.co.jp のナビ
aeon-kyushu.info:      戻り 3,807字 リンク30本 → 同じ
hmv.co.jp:             戻り 3,988字 リンク36本 → この中に記事が混ざっていた（5件取れた）
```

HMV で取れたのは運です。**検索の道は、いま安定して結果を返していません。**

### 判断してほしいこと
1. この2社（と残り11社）に `search` を足すか。**いまの検索の道では増えません**が、検索が直れば効きます。
2. それより先に**検索の道そのものを直すか**（Yahoo が結果を返していない・JSで描画かボット判定）。こちらのほうが13社に一度に効きます。
