### ★ `test_lottery_overrides.管理用の控え` はデータの実害（直していない）

**試験は正しく、データが壊れている。**

```
同じ round_id なのに、配布行と控えで event_id が違う行が5件

  行   evt_e1964be6…#rnd_a27e543a232acc97
  控え evt_a32d5c31…#rnd_a27e543a232acc97   ← 同じ rid・別の eid

配布行 405 / 刻んだ 404 / 控え 404 / 欠け 5
控えにあって配布行に無い鍵も 5（同じ5組の裏返し）
```

**TierOne 渋谷店の2件は互いに `event_id` が入れ替わっている**
（`evt_c949…#rnd_852a` と `evt_f540…#rnd_7b84` が交差）。

管理画面はこの鍵で控えを引くので、**この5行は「ID準備中」になり、更新が409になる**
（試験の説明文にそう書いてある実害が、いま起きている）。

**素性の付け替えが控えに反映されていない。** 直すのは `event_id` 台帳の側で、
試験を直す話ではない。**推測で触ると #1469 と同じ形になる**ので、原因と実害を
`test_data_contract` の一覧へ書き残してある。

## 2. CI ログから試験名を数えないこと

今日**3回**、別々の理由で間違えた。

```
① コンソールが日本語を化けさせ、化けた行が結合して多く数えた
② ASCII のモジュール名で数えたら、**別の試験が印字した記録済みログの中の
   `FAIL:`** を数えていた（`##[group]` に `rebase` `7.2` と一緒に出る）
③ 存在しない試験名（`def` が無い）を「落ちている」と読んだ
```

**信用できるのは `failures + errors` の数だけ。** 名前は手元で走らせて確かめる。
