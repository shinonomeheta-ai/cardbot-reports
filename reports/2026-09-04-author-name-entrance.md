1文字も変わりません。**

```

  日本語だけ                                      258
```

## 前回の整理の訂正

前回「265 種はどこにも表示名が存在しない」と書きました。事実としては正しいのですが、
**その理由を「情報が失われたから」と読んでいました。今回の実測はそうではないと示しています。**
これらの店名は**元からその形**です。正規化名と表示名が同じなので、
どこを探しても「より良い表記」が見つからなかった、というのが正しい読みです。

「壊れた名前が台帳へ入ってきている」という整理も、**269 種のうち少なくとも 122 種
（そのまま一致 97 ＋ 掃除して同じ 25）については当たっていません**。
残る 147 種は、良し悪しを判定する材料がまだありません。

## 3. publish-report.sh で本文が空になった（同じ事故の2回目）

**この報告は、最初の push で本文が空のまま上がりました。**（`9abf371`）
原因は `publish-report.sh` の次の行です。

```bash
if [ -n "$SRC" ]; then cp "$SRC" "$DEST"; else cat > "$DEST"; fi
```

第2引数を省くと標準入力から読みますが、こちらの実行環境では**標準入力が空**です。
`cat > "$DEST"` は**先に書いておいた本文を切り詰めてから**空を書き込みます。

INDEX の 2026-09-04-shared-platform-gate.md の行に「初回 push が空になった事故」と
書いてあるのと**同じ事故**です。文章の注意書きだけでは 2 回目が起きました。

そこで**スクリプトに関門を足しました**（この報告と同じ commit）。

```bash
# 本文が空になったら push しない（2026-09-04 追加・2回目の事故）
if [ ! -s "$DEST" ]; then
  <元に戻す>
  exit 1
fi
```

`$SRC` を省いたときも、書き込んだ結果が空なら **push せずに元へ戻して止まります**。

   本当に困っているのは正規化名そのものではなく、**表記ゆれで同じ店が二重に扱われること**で、
   それは出口（#1276）が直します。
