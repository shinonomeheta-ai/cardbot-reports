### 取得元と応募先を分けた理由（実測）

同じURLを両方に置くと、`candidate_contract.row_evidence` が**畳んで応募先が消えます**。

```
source_url = 商品ページ、apply_url = 同じ商品ページ
   → apply_url_status: candidate_rejected ／ apply_evidence 0本

source_url = 検索ページ、apply_url = 商品ページ
   → apply_url_status: found ／ has_application    ← こちら
```

試験に固定しました（`test_取得元は検索ページ応募先は商品ページ`）。

## 2. 締切なしの行が配布まで届くか（追って確かめました）

**答えは「人が確認すれば出る。自動では出ない」です。**

```
AIレーン   promote_candidate_decisions.AI昇格できるか
             end = apply_end[:10];  if not end or end < 今日: → "ended_or_no_end"
           **締切なしは必ず落ちる**
人のレーン  新規行を組む → store と product があれば通る（締切は要らない）
```

いまの配布 317 行に `apply_end` が空の行が0件なのは、この関門のためです。

M1g のカードは `start_only` なら回の有無に関わらず「不定期受付」を出すので、
**画面はいまのままでも変わりません**。ただし
**Amazon の回を行として自動で出したいなら、`ended_or_no_end` を
「締切なしは許す」形へ変える必要があります。**

配る側の外部仕様なので**この PR では触っていません**。判断をお願いします。
