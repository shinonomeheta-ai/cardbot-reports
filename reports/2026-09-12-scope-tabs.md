# 店の区分をタブに、絞り込みは一段下・左寄せへ（PR #1545・本番反映済み）

2026-09-12 / 本人指摘

> 大手チェーンを分かりやすいでかいタブかボタンかなんかにして、大手チェーンと支店と
> 全てに分けて。その中で絞り込みだから一段下でしょ、絞った後。なんで同じ段にあるの？
> 左に寄せなよ、フィルター。
> ていうか大手チェーンとかのやつはもう完全に、ボタンじゃなくてタブかなんかにして。
> 意味わかんねえよ。

## 何を間違えていたか

同じ日の午前に **「区分とチェックを1段にまとめる」** 直しを入れていた（#1528）。
本人の前の指摘（「次のフィルターを下の段にしてすげえ見にくい」）を
**「段が多いのが悪い」** と読んだが、本当の理由は **形が同じだったこと**。

選ぶものは2種類ある。

* **見る対象そのもの**（大手チェーン／支店／その他／すべて）＝節が変わる
* **その中の絞り込み**（チェック・確認状態）

これを同じ丸札で並べたので、どちらが上位か読めなかった。段の数ではなく
**形を変える**のが正しい直しだった。

## 直した形

```
┌ すべて 1789 ┬─ 大手チェーン 140 ─┬ 支店 332 ┬ その他 1317 ┐   ← タブ（16px・現在地は地色＋太字＋下線）
└─────────────┴────────────────────┴──────────┴─────────────┘
チェック   [すべて 140][システムのみ 118][人チェック 22]            ← 絞り込み（一段下・左寄せ・13px）
確認状態   [すべて 140][人の確認まち 104][…AI指摘あり 14][確認済み 0][掲載しない 22]
[ 店名・商品名・取得元を検索                ][絞り込み]
```

* 区分は `role="tablist"` / `role="tab"` の**本物のタブ**。現在地は
  `aria-selected` ＋ 地色 ＋ 太字 ＋ 下線の4つで示す（色だけで言わない）
* 絞り込みは**タブより下の段で左寄せ**、札は一回り小さい（上下の関係が見た目で分かる）
* 使われなくなった丸札の帯（`.tabStrip` / `.cat` / `.catOn`）は外した
  （死んだCSSクラスを拾う試験がある）

## 測ったこと

| 何 | 結果 |
| --- | --- |
| `node --test app` | 3,750 / 3,750 pass |
| CI build / test / Vercel | **すべて緑**（この枝では python の実データ試験も緑だった） |

「区分とチェックは同じ段」を固定していた試験は、**逆の規則**へ置き換えた
（タブが上・絞り込みが下・左寄せ・タブの字のほうが大きい）。

本番（マージ `0138dced`・Vercel success）の admin の実体
`page-d7effaa7a4a998f3.js` に `scopeTabs` / `tablist` / `filterTier` が入り、
**旧の丸札クラスは消えている**ことを確認した。

## 積み残し

操作部（画面の上端〜一覧の上端）は 184px → **242px**。本人の決まりは140pxなので
**102px 超過**している。タブを大きくし、絞り込みを別の段へ下ろした結果で、
いまの3つ（タブ・絞り込み・検索）を全部出したままでは140pxに入らない。
畳むなら候補は次の3つ。

1. 確認状態を「絞り込み」パネルの中へ入れる
2. 検索欄を絞り込みの段へ寄せる
3. 140pxの決まりを、軸が増えたぶん見直す
