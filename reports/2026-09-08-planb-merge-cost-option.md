## metrics の案は正しいが、いま単体で入れると**費用が増える**

metrics から「指紋に版ではなく抜粋そのものを混ぜる形なら聞き直しを 102回へ
絞れるのでは」という案が出た。**単体で今日入れると、278回が浮くどころか
全件が1回聞き直しになる。**

`cache_fingerprint` は `candidate_ai_contract.input_fingerprint()` の材料の1つで、
最後に材料ぜんぶを JSON にして SHA を取っている。

```python
種 = json.dumps(fingerprint_material(candidate, round_, prompt_version,
                                    model, cache_fingerprint), ...)
return hashlib.sha256(種.encode("utf-8")).hexdigest()[:16]
```

**書き方（`v17:abc` → `abc`）を変えると、中身が同じでも SHA が変わる。**
保存済みの結果は古い書き方で計算した指紋を持っているので、**全部が
「材料が変わった」**になる。抜粋 ok × active は 1,124回（答えあり 393・
未実行 731）なので、393 では済まない。

## 【選択肢】只で済む瞬間は「どのみち全件聞き直しになる版上げのとき」＝今回

```
案1  #1468 だけ入れる
       いま        393回 聞き直し（うち278回は抜粋が同じ）
       次に切り方を変えるたび  また全件

案2  #1468 と同時に、指紋から版を外す
       いま        393回 聞き直し（**案1と同じ・追加費用 0**）
       次からは    **抜粋が実際に変わった回だけ**（今回で言えば102回ぶん）
```

外して安全と言える理由は1つだけ。`cache_fingerprint` の中身は既に
**抜粋そのもののハッシュ**（`content_fingerprint`）なので、**抜粋が1字でも
変われば指紋は変わる**。版は「切り方が変われば意味も変わる」ために足されて
いるが、**AI が見るのは本文だけ**なので、本文が同一なら前の答えはそのまま正しい。

### 私から勝手に入れない理由

1. `test_版を上げて旧版はstale`（`startswith("v3:")`）と
   `test_版が変われば入力の指紋も変わる` は、**いまの規則をわざと書き留めた守り**。
   規則そのものを変える話なので、書き換えてよいかは本人の判断だと思う
   （「規則が変わっていないのに試験を直す」のとは別だが、線の上にある）
2. AI へ送るかどうかの判定＝**課金の経路そのもの**

**案2 を採る場合でも、いま払う額は案1 と同じ**（追加費用 0）。違うのは
「次の切り方の変更からいくら払うか」だけ。
