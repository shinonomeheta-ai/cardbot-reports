## 1. 「完全一致」は社を落としていません

正規化（NFKC ＋ 全角括弧→半角 ＋ 空白除去 ＋ 小文字化）して数え直しました。

**1社も増えません。** 表記ゆれで落ちている社はありませんでした。

### ご指摘の2例は、どちらも「数え落とし」ではありません

**iAEON**

```
store_keys   「イオン九州 (iAEON)」  ← ある
配布行        （無し）              ← イオン九州/iAEON を含む行が lotteries.json に1本も無い
```

**行そのものが配布データに出ていません。** 表記の問題ではなく、**収集か配布の関門で
落ちている**か、そもそも取れていません。数え方を直しても社数は増えません。

**SuperKaBoS**

```
配布行        SuperKaBoS＋ゲオwasse店（〜2026-09-07T23:59・受付中）ほか
store_keys   （無し）              ← SuperKaBoS はゴールデンチェーンに入っていない
```

**受付中の行はありますが、M1g の52社に入っていません。** 表記ゆれ（全角＋／半角+）は
実在しますが、**寄せる先の `store_keys` が無い**ので、正規化しても当たりません。
（`SuperKaBoS⇔CARDBOXワッセ店` は以前からの登録候補です。）

### 前方一致にすると支店を数えてしまう

完全一致しない店名165のうち、寄せて前方一致させると39が当たりますが、
**39件すべて支店**でした（`TSUTAYA五所川原店` `TSUTAYA大垣店` …）。
§3-1-1-c は「支店の告知はカードに入れない」なので、**前方一致にするのは誤り**です。

### 結論

**正本の数え方はこのままで確定してよい**と考えます。26社の差は
**文字列の一致の問題ではありません**。iAEON の例が示すとおり、差の中身は
「配布行が出ていない」（＝収集か関門の問題）です。
