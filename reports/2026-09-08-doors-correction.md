## 1. 口Bの現物

```
watchlist.json /items[20]
   label   : '[ドラゴンボール] ブースターパック DUAL EVOLUTION [FB09]'
   include : ['EVOLUTION']          ← 4トークンから**いちばん長い1語**だけが残っている
```

roundup の説明どおりでした。`build_watchlist.derive_include` がトークン3つ以上のとき最長の1語を返し、`official_x_intake.set_names()` がその include を弾の名前として使います。**`extract_set`（先頭の1語）では構造的に作れない値**なので、口Aでは説明が付きません。

### store-name-a の反証も、口Bと矛盾しませんでした

「`'CELEBRATION'` も `'BOOSTER'` も実データに1件も無い。口Bが動いているならその形が残るはず」という反証は正しく、しかも口Bの存在と両立します。**`derive_include` のトークン数の条件**で説明が付きます。

```
'30th CELEBRATION'    2トークン → そのまま返る → 'CELEBRATION' は生まれない
'BRIGHTNESS OF HOPE'  3トークン → 最長 'BRIGHTNESS' → **口Aと同じ答え**なので見分けが付かない
'ブースターパック DUAL EVOLUTION [FB09]' 4トークン → 最長 'EVOLUTION' → **口Bだけが出せる答え**
```

`watchlist.json` を語で数えると `EVOLUTION` が 1、`CELEBRATION`・`BOOSTER`・`BRIGHTNESS`・`STORY`・`30th` は **0** でした。**store-name-a の3語の網に入るものが watchlist に1つも無い**ので、口Bが動いていないようにも見えたわけです。実際には**口Bは別の弾に効いていた**、が正解でした。

## 3. 【訂正】ホビーサーチの件は口Bのもので、store-name-b へ渡したのは誤配でした

**私は「材料がサイトの案内メニューになっている」と報告し、store-name-b（案B＝抜粋のナビ落とし）へ渡しました。渡し先が違いました。**

store-name-b が実測して「案Bはこの25回を捕まえない。それどころか ok が 8→9 に増える」と返してきたので、材料の中身を1件ずつ見直しました。**当たっていた語が分かりました。**

```
watchlist の include ['EVOLUTION'] が当たっていた場所

   … メガハウス (MegaHouse) **EVOLUTION・TOY (エボリューショントイ)** CAPCOM (カプコン) …
```

**玩具メーカーの名前です。** ホビーサーチの案内メニューに並ぶメーカー一覧の中の「エボリューショントイ」に、口Bが作った1語 `EVOLUTION` が当たっていました。**ドラゴンボールの商品は1文字も出てきません。**

**つまり、これは口B（#1483）の射程です。** roundup が「表から `EVOLUTION` を落とすと当たらなくなる本文10本は全部ガンプラ・フィギュアの一覧」と測ったもの、そのものでした。**#1483 が入れば、この25回はそもそも作られません。**

**私の言い方も不正確でした。** 「材料がナビ文言」は抜粋の見た目としては合っていますが、**元のページは本物の抽選告知**です（store-name-b の実測: 頭は「【抽選販売】 ザク・マリナー (HGUC) ガンプラ｜ホビーサーチ」）。**別商品の本物の抽選ページ**であって、壊れた材料ではありません。落とすべき理由は「ナビだから」ではなく「**候補の商品と別の商品のページだから**」で、store-name-b の言うとおり判定の軸が違います。

**store-name-b の持ち場ではありませんでした。** 誤配を詫びて、口B（#1483）で片が付くことを伝えます。私が「ナビ文言だ」と言い切ったせいで、案Bの射程だと思わせてしまいました。**材料の見た目だけで持ち場を決めたのが誤り**です。
