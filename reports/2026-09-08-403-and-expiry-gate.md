## 1. 403 の切り分け — 原因候補3つは全部はずれ

evidence 側で `http_403` の41本を URL へ戻すと **15ホスト**でした（うち8つが `membercard.jp`）。evidence の形から1つずつ page cache 側へ寄せて当てました。

| | UA を 120 へ | 転送を追う | Accept を外す |
| --- | --- | --- | --- |
| membercard.jp 8ホスト | 変化なし | 変化なし | 変化なし |
| aeonretail・joshinweb | 変化なし | 変化なし | 変化なし |
| kidsrepublic・suruga-ya | 変化なし | **301 → 200** | 変化なし |
| 1999.co.jp | 変化なし | 301 → **403** | 変化なし |

**UA も Accept も、15ホストのどれも動かしませんでした。** 転送を追うと2ホストだけ通ります。

### 本命はこれでした

```
dorasuta.membercard.jp   素の取得 error 0字  →  描画 28,605字
aeonretail.com           素の取得 error 0字  →  描画 470,128字
joshinweb.jp             素の取得 error 0字  →  描画    276字
```

`official_page_intake.読む` は素の取得が落ちると `url_quality.render_text`（headless Chrome）へ切り替えます。`candidate_evidence_fetch` に**その道がありません**。metrics の「隣のレーンは2〜3万字で取れている」の 28,605字 と一致します。

**ヘッダーの違いではなく、ブラウザで開くかどうかでした。** 私が原因候補として3つ挙げたのは的外れで、レビュー側にもその3つで切り分けを指示させてしまいました。

joshinweb は**描画しても276字**なので、描画を足しても直りません。15ホストのうち直る見込みがあるのは、描画で本文が出た2ホストと転送で通った2ホストです。

**①の実装（描画を足すか、隣の本文を使うか）は判断待ちにします。** 「隣の本文を使う」だけでは joshinweb のように隣も持っていないものは直りません。

## 2. 締切の関門（#1470）— 条件を1つ変えました

### 何が無かったか

`ec_lottery_watch.py` と `official_site_watch.py` の候補を作る所に**締切の関門がありません**でした。抽選記事と判定できれば、締切がいつでも行にします。

### 指示の文言どおりに書いたら壊れました

「条件は応募の締切だけに絞る」の狙いは「当選発表の回は締切が過去でも要る」を守ることでした。**そのとおりに書くと、その回が消えます。**

守りたい相手は「締切は過ぎたが発表はこれから」の回で、**その回は同じ行に両方の日付を持ちます**。締切だけを見て作らないと、発表の側ごと落ちます。metrics が8本を挙げて止めてくれました。

私は締切だけで実装を終え、試験にも「締切は過去・発表は未来 → 終わっている」と書いていました。**止めてもらわなければそのまま出していました。**

### 採った条件

> **応募の締切が過去 かつ（当選発表日が無い または 発表日も過去）**

実測（台帳3,032回）。

| | 回 |
| --- | --- |
| 締切が過去で**止まる** | 1,378 |
| 締切は過去だが**発表がこれからで残る** | **146** |

metrics の8回は「生まれた時点で締切が過ぎている159回」の中の数で、私の146回は台帳の全回で数えたものです。母数が違うだけで同じことを言っています。

### 作り

- 判定は `official_page_intake.応募が終わっている(row, now)` の**1本**。2つの入口から呼びます。
- 試験で「両方が呼んでいること」と「どちらも `end_of_day=True` を自分で書いていないこと」を見ます。
- 止めた数は `expired` として集計に出します。黙って捨てません。
- **既にある行は触りません。** 下ろすのは配信の関門の仕事です。
- 締切が空・読めないときは作ります。発表日が読めないときは締切だけで決めます。

試験は新規6件が緑、周辺155件で新しい赤なし。
