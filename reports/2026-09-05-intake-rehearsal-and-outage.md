## 2. 【事故】私が公式X巡回を26分止めました

### 何が起きたか

前回の #1283（予行演習の追加）で、alert ステップに `env:` を**2つ**書きました。
GitHub は

```
failed to parse workflow: (Line: 145, Col: 9): 'env' is already defined
```

を返し、**official-x-intake ごと起動できない**状態になりました。

気づいたのは、承認いただいた予行演習を手で流そうとして 422 が返ったときです。
**流そうとしなければ、次の巡回の枠（14:00 JST）まで気づけませんでした。**

### なぜ手元で気づけなかったか

**`yaml.safe_load` は重複鍵を黙って受けます**（あとに書いた方で上書き）。
私は「yaml OK」と確認して出しましたが、その確認では素通りする壊れ方でした。
手元で通り、GitHub で落ちる。

### 時系列

| 時刻(UTC) | |
| --- | --- |
| 2026-09-04 23:01 | 最後に成功した巡回（JST 08:01 の枠・repository_dispatch） |
| 2026-09-05 00:24 | 私の push で workflow が読めなくなる（ブランチ） |
| 00:47 | #1283 をマージ → **main が壊れる** |

| 01:13 | #1284 をマージして復旧 |

**巡回の枠は1つも落としていません。** 次の枠は 14:00 JST（05:00 UTC）で、
その3時間50分前に直っています。

### 直したこと

1. `env:` を1つにまとめた（中身は同じ）
2. **重複鍵を見つける読み方**で全 workflow を読む試験を足した
   （`test_workflow_yaml_duplicates.py`）。直す前の版に当てると
   `official-x-intake.yml: 鍵 'env' が二度書かれています` で落ちる

「`safe_load` では見つからない」ことも試験にしました。将来 `safe_load` が
弾くようになったら、その試験が落ちて「この検査はもう要らない」と分かります。

### この事故から分かったこと（設計上の穴）

**読めない workflow は、自分が壊れたことを知らせられません。** 昨日
`alert_incident.py failure` の配線を足しましたが、**workflow が parse できない
ときは1ステップも走らない**ので、あの通知は出ません。

いま残っている網は health-watch（12時間動いていなければ鳴る）だけです。
今回は12時間より早く気づけましたが、それは**たまたま予行演習を流したから**です。
