## 2. CI の型分け — 何をやっているか

赤には性質の違う3つが混ざっている。

```
A 規則の検査          外を読まない            決定的。python-test に置く
B いまのデータの状態  lotteries.json など     巡回が20〜30分ごとに書き換える
C 外の状態で腐る      現在時刻・月次予算残高  日付が変わる／残高が積むと落ちる
```

B を `python-test.yml`（`unittest discover`）に置いていると、**コードを1行も
触っていない PR が巡回のせいで赤くなる**。基準を取っても20分で腐る。

### 仕組み（#1494）

```
data_check.py    印は1か所（実データの検査）
data-contract    export CARDBOT_DATA_CHECK=1

python-test   飛ばす → **PR の赤は必ずコードのせい**になる
データ契約     走る  → 押す直前・その回のデータ・落ちたら push を止める
```

### 手順（**この順を崩さない**）

```
① 1件ずつ実際に走らせて型を確かめる（名前では区別できない）
② B なら data_check.実データの検査 の印を付ける
③ **契約の一覧へは入れない。** test_data_contract.移行中の実データ検査 へ書く
④ 中身を直して実データに対して緑になってから、契約の一覧へ移す
```

**③を飛ばして契約へ入れると、PR の赤は消えるが巡回が止まる**（契約は push を
止める関門）。手元で確認済み——4件を入れたら契約 108件中4件が赤になった。

### 移行中の7件（＝直す約束）

```
test_candidate_ai_runner.抜粋の版Tests        CL.load（候補台帳）
test_candidate_ai_runner.支店の境界Tests      同上
test_lottery_overrides.管理用の控えTests      lotteries.json
test_event_id_redirects.リダイレクト台帳Tests event_id_auto_redirects.json が混ざる
test_shadow_url_owner.配る側とそろっている    lotteries.json / store_platforms
test_url_fields.配る側と同じ答え              LOT_PATH / store_platforms
test_shared_platform_gate.公開データも直してある  lotteries.json
```

**`test_event_id_redirects` の原因は特定済み。** `EI.event_id_redirects(path)` は
**人の台帳（`path` で差し替えられる）と機械の台帳（`auto_redirects_path()`・
差し替えられない）を合わせて返す**。試験は人の台帳だけ差し替えて「1件だけ返る」と
期待しているので、機械の台帳に行が増えた日から落ちる。**バグではなく、試験の
期待が仕様と食い違っている。**

## 4. 触ると危ないところ

* **`lottery_io.save()`** — 配るデータを書くいちばんきわどい場所。`round_id` は
  `守る()` で発番され `_古い応募回を外す()` で外れる。**出入りするので書き出す
  直前が唯一の確定点。** 手元では巡回の挙動を再現できない（`本番` の判定が path で
  変わる）ので、**推測で行を消す処理を入れない。計測器を先に**（#1490 → #1491）
* **データ契約** — 落ちたら push を止める。**赤いものを入れると巡回が止まる**
* **`test_data_contract.load_tests`** — クラスを作っただけでは素通りする。
  **配線を忘れると「緑のまま何も見ていない」**（今日3回踏んだ型）
* **印を付けるスクリプト** — 「ファイル全体に印の文字列があるか」で判定すると、
  **理由文が同じ2件目が黙って飛ばされる**（#1495 で実際に起きた）。
  **クラス宣言の直前の行**で判定し、付けたあとに `__unittest_skip__` を実際に読む
